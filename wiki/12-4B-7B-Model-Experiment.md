# 4B·7B 양자화 모델 실험

## 목적

현재 사용 중인 qwen3:0.6b·1.7b보다 큰 모델이 RAM 8GB CPU 환경에서
실제로 사용할 수 있는지 확인한다.

## 대상

| 순서 | 모델 | Ollama 기본 양자화 | 파일 크기 | 용도 |
|---:|---|---|---:|---|
| 1 | qwen3:4b-instruct | Q4_K_M | 약 2.5GB | 차기 주력 후보 |
| 2 | qwen2.5:7b-instruct | Q4_K_M | 약 4.7GB | 한계 성능 비교 |

## 설치

```powershell
ollama pull qwen3:4b-instruct
ollama pull qwen2.5:7b-instruct
```

## 단계별 시험

1. Ollama와 PowerShell만 실행한 상태에서 qwen3:4b-instruct 단독 응답을 확인한다.
2. FastAPI 화면에서 qwen3:4b-instruct를 선택하고 지원금 RAG 질문을 시험한다.
3. 첫 문항 벤치마크와 작업 관리자 메모리를 기록한다.
4. 문제가 없을 때만 qwen2.5:7b-instruct에 같은 절차를 적용한다.
5. 두 모델을 동시에 메모리에 유지하지 않는다.

```powershell
python benchmark.py --models qwen3:4b-instruct --max-cases 1
python benchmark.py --models qwen2.5:7b-instruct --max-cases 1
```

두 모델이 모두 안정적일 때만 다음 전체 비교를 실행한다.

```powershell
python benchmark.py --models qwen3:4b-instruct qwen2.5:7b-instruct
```

## 기록 항목

- 모델 최초 적재 시간
- 평균 응답시간
- 평균 token/s
- 작업 관리자 전체 메모리 사용량
- 자동점수와 사람 검토 결과
- RAG 답변의 출처·금액·날짜 검증 여부
- 멈춤, 가상 메모리 사용 또는 오류 발생 여부

## 중단 기준

- Windows가 장시간 응답하지 않음
- 지속적인 디스크 사용과 심한 입력 지연 발생
- Ollama 모델 적재 실패 또는 메모리 오류
- 데모에 사용하기 어려울 정도로 생성속도가 낮음

7B가 중단 기준에 해당하면 삭제하지 않고 비교 결과만 기록하며,
실제 데모 모델은 qwen3:4b-instruct 또는 qwen3:1.7b로 유지한다.

## 2026-08-25 사전 시험 메모

- `qwen3:4b`로 두 차례 시험했으나 256 생성 토큰을 사고 과정에 모두 사용해
  각각 61.594초·5.62 token/s, 88.422초·4.80 token/s, 자동점수 33.3을 기록했다.
- 두 결과는 최종 답변이 잘린 Thinking 전용 모델의 결과이므로 일반 답변 품질
  비교표에는 포함하지 않는다.
- Ollama 태그 확인 결과 `qwen3:4b`와 `qwen3:4b-thinking`이 같은 모델 해시를
  사용하므로 이후 시험 대상을 `qwen3:4b-instruct`로 변경했다.

### 중간 결론

- 4B Instruct는 8GB RAM CPU 환경에서 중단이나 메모리 오류 없이 실행됐다.
- 자동점수는 기존 0.6B·1.7B의 80.0보다 높았지만 차이는 3.3점이다.
- 1.7B보다 생성속도가 약 절반이고 평균 전체 시간은 약 2.2배 길다.
- 모델 크기가 커져도 형식 위반과 REST API 사실 오류가 남아 있으므로 RAG와
  검증 하니스는 계속 필요하다.
- 7B는 전체 평가 전에 한 문항만 실행하고 Windows 메모리와 입력 지연을 확인한다.

답변은 요구한 한국어 두 문장을 마지막에 생성했지만, 그 앞에 질문을 재해석하는
중국어 문단을 길게 출력했다. 기존 평가기는 한글과 영문만 비교해 한자를 계산에서
제외했기 때문에 이를 100점으로 잘못 판정했다. 모든 문자권의 글자를 분모에 포함하도록
평가기의 한국어 비율 계산을 수정한 결과, 한국어 비율은 0.503이고 수정 점수는 66.7이다.

생성 토큰 126개와 3.16 token/s를 기준으로 순수 생성에만 약 40초가 걸렸고,
모델 적재 등을 포함한 전체 시간은 약 117초였다. 7B 모델은 이 PC에서 실행은
가능하지만 응답시간과 언어 지시 준수 모두 데모 기준을 통과하지 못했으므로 5문항
전체 평가는 생략한다.

## RAM 8GB 당시 모델 선택

- 빠른 개발 확인: qwen3:0.6b
- 현재 사용자 데모: qwen3:1.7b
- 품질 비교·선택적 데모: qwen3:4b-instruct
- 하드웨어 한계 확인용: qwen2.5:7b-instruct

## 2026-09-23 RAM 16GB 재평가

PrivAI PC의 RAM을 8GB에서 16GB로 증설한 뒤 같은 모델과 5문항 평가셋으로
1.7B·4B Instruct·7B Instruct 양자화 모델을 다시 측정했다.

| 모델 | 문항 | 평균 시간 | 평균 속도 | 평균 자동점수 |
|---|---:|---:|---:|---:|
| qwen3:1.7b | 5 | 7.959초 | 13.99 token/s | 80.0 |
| qwen3:4b-instruct | 5 | 16.034초 | 6.80 token/s | 83.3 |
| qwen2.5:7b-instruct Q4_K_M | 5 | 28.539초 | 3.80 token/s | 90.0 |

8GB 환경에서는 7B 첫 문항에 117.257초가 걸리고 전체 평가는 생략했다.
16GB 환경에서는 7B 첫 문항 콜드 런이 43.729초로 줄었고 전체 5문항 평가를
중단 없이 완료했다. 모델이 RAM에 올라온 뒤의 별도 웜 런은 19.415초였다.

자동점수 90.0은 형식과 핵심어 점수이며 사실성 90점을 의미하지 않는다.
7B도 개인정보 보호 효과와 POST 보안을 과도하게 단순화했으므로 RAG와
검증 하니스가 계속 필요하다.

### 7B를 PrivAI 기본 모델로 사용하지 않는 이유

qwen2.5:7b-instruct Q4_K_M은 RAM 16GB에서 안정적으로 실행되고 전체 평가도
완료했지만 평균 응답시간이 28.539초이고 평균 생성속도가 3.80 token/s다.
4B Instruct의 평균 응답시간 16.034초와 6.80 token/s보다 느리지만 사람 검토
사실성은 뚜렷하게 우수하지 않았다.

따라서 7B 모델은 PrivAI 기본 모델로 사용하지 않는다. 현재 기본 데모는 빠른
qwen3:1.7b를 유지하고, qwen3:4b-instruct는 균형 모드 후보, 7B Instruct
Q4_K_M은 시간이 허용되는 정밀 모드 후보로 사용한다.

### 발견한 오류

`4B Instruct 전체 평가의 평균 생성속도는 몇 token/s야?`라는 질문에서 Wiki 검색은
정확한 4B 표를 첫 번째 근거로 찾았지만, 표 추출기가 `평균 속도` 열을 인식하지 못해
두 번째 근거인 웹 프레임워크 표의 값을 답했다. 기존 검증은 잘못 선택한 표 안에서만
값을 비교해 이를 통과로 표시했다.

### 수정

- `생성속도`뿐 아니라 `평균 속도` 등 `속도`가 포함된 열을 token/s 열로 인식
- 질문에 `4B`, `Instruct` 같은 모델 식별자가 있으면 해당 모델 행을 우선 선택
- 속도·점수·이유처럼 여러 요구가 섞인 질문은 단일 표 수치 답변으로 축소하지 않음
- 잘못된 프레임워크 표 선택과 복합질문 회귀 테스트 추가

### 재시험 결과

| 질문 | 결과 | 검증 | 시간 |
|---|---|---|---:|
| 4B 평균 생성속도 | qwen3:4b-instruct 5.00 token/s | 표 수치 검증 통과 | 즉시 조회 |
| 7B 전체 평가 생략 이유 | 응답시간과 언어 지시 준수가 데모 기준 미달 | 출처 연결·사람 검토 필요 | 69.588초 |

검색·표 추출·출처 연결은 정상화됐지만 4B의 생성형 RAG 답변은 69.588초,
4.05 token/s로 느렸다. 확정 가능한 표 수치는 결정론적으로 즉시 답하고, 의미 요약이
필요한 질문에만 LLM을 호출하는 현재 하니스 전략이 이 PC에서 특히 중요하다.
