# v0.1.0 마일스톤 — 검증형 로컬 RAG MVP

날짜: 2026-08-14

## 출발점

목표는 외장 GPU가 없는 Windows 11 PC에서 경량 LLM을 실행하고, 공모전 주제에 맞게 바꿀 수 있는 공통 기반을 만드는 것이었다.

기준 하드웨어:

- Intel Core i3-7100
- RAM 8GB
- Intel HD Graphics 630

## 1. 웹 프레임워크 실험

FastAPI, Flask와 Streamlit에서 동일한 Ollama 코어를 사용했다.

- FastAPI: 주력 REST API
- Flask: 최소 구현 비교
- Streamlit: 빠른 AI UI

모델 생성속도는 세 환경 모두 약 11~12 token/s로 비슷했고 전체 시간 차이는 모델 적재와 답변 길이의 영향을 받았다.

## 2. 모델 실험

qwen3:0.6b와 qwen3:1.7b를 비교했다.

| 모델 | 평균 생성속도 | 결론 |
|---|---:|---|
| 0.6B | 24.45 token/s | 빠른 개발 테스트 |
| 1.7B | 10.28 token/s | 사용자 데모 |

작은 모델은 빠르지만 계산 오류, 지시 반복과 부정확한 설명이 확인됐다. 1.7B도 자체 지식만으로는 안정적이지 않았다.

## 3. 로컬 RAG

Obsidian Wiki를 제목 단위로 분할하고 BM25로 검색했다. 벡터DB와 임베딩 모델 없이 8GB 환경에서 동작하는 기준선을 확보했다.

검색 가이드의 예시 질문이 노이즈가 된 문제를 발견해 코드 블록을 색인에서 제외했다. 관계가 약한 보조 출처는 1위 점수의 30% 미만일 때 제거했다.

## 4. 근거 검증 하니스

모델이 평균 속도 질문에서 평균 시간 열을 선택하는 오류가 발생했다. 이를 계기로 Markdown 표를 구조적으로 파싱하고 질문 단위와 열 이름을 대응했다.

추가로 날짜, 금액과 단위 수치를 근거 원문과 대조했다. 일반 서술문은 자동 검증 통과로 표시하지 않도록 UI 상태를 분리했다.

## 5. 문서 업로드

MD, TXT와 텍스트 PDF를 로컬 Markdown으로 변환해 Wiki에 자동 반영했다.

- 최대 5MB
- PDF 최대 100페이지
- 안전한 파일명
- SHA-256 중복 방지
- 업로드 원문 Git 제외

가상 지원정책 문서에서 월 10만원과 2026년 9월 30일을 정확히 답하고 원문 대조까지 통과했다.

## 6. 평가와 테스트

- 모델 자동 평가 5문항
- JSON·CSV·Markdown 보고서
- 사람 사실성 검토
- 자동 테스트 24개

자동점수와 실제 사실성이 다를 수 있음을 실험으로 확인했다.

## 7. 문서화 기준점

GitHub 공식 문서와 Obsidian 연구일지를 분리했다.

- 공식 문서: 설치, 아키텍처, API, 결과, 보안, 의사결정
- Wiki: 실험 과정, 오류, 수정과 다음 아이디어
- CHANGELOG: 버전별 변경
- ROADMAP: 다음 개발 순서

## v0.1.0 핵심 결론

1. 이 PC에서도 경량 LLM 데모가 가능하다.
2. 0.6B는 개발용, 1.7B는 데모용이 적합하다.
3. RAG만으로 사실성이 자동 보장되지는 않는다.
4. 확정 가능한 수치는 결정론적 코드로 검증하는 편이 낫다.
5. 개인정보 업로드 문서는 공개 저장소와 분리해야 한다.

## 다음 단계

BM25를 버리지 않고 기준선으로 유지한 채 경량 의미 검색을 비교한다. 표현이 다른 질문에서 검색 성공률이 실제로 개선되는지, RAM과 지연시간 비용을 함께 측정한다.
