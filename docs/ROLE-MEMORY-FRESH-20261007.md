## 화면 → API → Wiki → 응답 검증

- 이전 서버 세션을 종료하고 최신 코드로 127.0.0.1:8000을 실행했다. 새 서버 PID는 22380이다.
- 화면에서 빠른 모드 `qwen3:1.7b`, Wiki 사용, BM25를 확인했다. Ollama 연결 및 18개 문서·74개 조각 상태가 표시됐다.
- 별도 검증 탭에서 p01을 전송했다. 실제 화면에 역할, 문서·절 출처, 메모리 근거 부족 및 ‘일부 항목 원문 추출 · 미확인 항목 있음’ 상태가 나타났다.
- 이어 p04를 전송해 역할 누락과 안전 차단을 화면에서도 재현했다. 이 한계 확인 뒤 추가 화면 검증이나 구현은 진행하지 않았다.
- 서버 로그에서 GET /, /health, /models, /knowledge/status 및 두 POST /rag/chat/stream 모두 HTTP 200을 확인했다. HTTP 성공은 답변 요구 충족을 뜻하지 않는다.
- 브라우저 오류·경고 로그는 빈 목록이었다. 화면 증거는 부모 작업 폴더 `privai-fresh-check-20261007.png`에 저장했다.

검증 스킬에 따라 단순 테스트 통과뿐 아니라 실제 입력→스트리밍 API→근거 복사→화면 상태까지 확인했다. 새 서버는 계속 실행 중이다. 사용자 기존 탭은 변경하지 않았다.

## 다음 개선

‘최대·평균·최소’ 같은 측정 조건을 요구 항목으로 명시하고, 조건별 근거가 없으면 그 조건을 포함해 부족을 안내해야 한다. 동시에 확인 가능한 역할은 유지해야 한다. 단순히 문법에서 ‘최대’를 제거하여 일반 RSS 행을 최대값처럼 제시하는 방식은 피해야 한다.

이번 작업은 재시작 및 평가만 수행했다. 운영 코드 변경, Git 커밋·푸시는 하지 않았다.
