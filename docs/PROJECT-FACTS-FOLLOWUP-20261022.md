# 사용 질문 10개 후속 개선 — 2026-10-22

## 출발점

사용자가 1.7B에서 실행해 공유한 화면 10개를 Wiki 원문과 대조했다.
1·3번은 원문과 부합했으나, 2번의 화면 열 혼동, 4번의 전체 시간 누락과
개별 측정의 평균 표현, 5번의 과도한 보류, 6번의 확인 가능한 역할 누락,
7번의 HTTP 연동 추측, 8번의 모델 목록 누락과 부적합 출처,
9번의 USB 비교 질문을 단순 속도표로 대체, 10번의 검색 실패를 확인했다.

이 10개는 이제 개발 회귀 문항이다. 수정 후 통과를 새 질문에 대한 정확도나
1.7B 모델 자체의 성능 향상으로 해석하지 않는다. 원본 Wiki는 변경하지 않았다.

## 변경 내용

- `core/project_facts.py`: 제한된 전체 질문 문법을 통과한 경우에만 표의
  대상 열과 요청한 행을 직접 연결한다. 포트·화면·API 문서·역할을 구분한다.
  다른 이름·다른 셀 값을 넣은 통제 표로도 동작을 검사한다.
- 생성속도와 전체 시간을 함께 요청하면 모델·전체 시간·생성속도를 같이
  복사한다. 개별 기록을 평균으로 바꾸지 않는다. 기존 단일 수치 경로에서도
  실제 열 제목에 평균이 명시된 경우에만 평균이라고 부른다.
- ‘역할을 설명하고’ 표현을 기존 부분 답변 문법에 추가한다.
  Django를 만들지 않으면서 FastAPI·Flask 역할은 보존한다.
- 실제 통신·연동 구조는 역할 표나 일반 HTTP 지식에서 도출하지 않는다.
  역할은 복사하고 구조는 별도 근거 검토 필요로 표시한다. 명시적 연동 문서의
  일반 의미 판독 기능을 구현한 것은 아니므로 보수적 미확인이 남을 수 있다.
- 성능 우열 판단에는 원문의 비교 한계를 제시하고, USB 이전 후 재현성
  질문에는 기존 속도표를 답으로 대신하지 않는다. 임의 새 수치·실측은 없다.
- 모델 질문은 모드 표와 기본 모드 결정 문단을 보충 검색해 직접 복사한다.
  이것이 현재 설치된 모든 모델이나 실행 상태를 실시간 조회한 결과라고
  주장하지 않는다. 임베딩 모델을 포함한 설치 목록 조회 기능과는 별개다.
- 프로젝트 요약은 검색된 역할·모드·결정 기록 일부를 보여주되,
  전체의 최신 검증 완료·미완료 현황을 확인했다고 주장하지 않는다.
- 보충 검색은 선택한 검색 모드를 유지한다. 새 경로는 최대 4질의,
  질의당 3결과, 새 조각 최대 6개이며 전체 파일의 숨은 전수 탐색은 없다.
  첫 검색이 빈 프로젝트 요약도 이 제한 안에서 보충한다.
- 충돌 셀·빈 셀·미지원 추가 요구는 임의로 완성하지 않는다. 기존 역할 충돌,
  연도·모델 조건, 메모리 및 고정 문맥 실험 경로는 유지한다.

## 검증과 한계

- pytest 전체 499개 통과. 이번 추가 49개는 10문항의 일반/스트리밍 경로,
  실제 Wiki, 통제 표, 충돌·추가 요구·검색 한도·검색 모드·조건 검사를 포함한다.
- FastAPI·Flask 실제 앱의 테스트 클라이언트에서 2·4·6·7·9번 스트리밍
  응답 10개를 확인했다. 모델 호출을 금지한 상태에서 출처·미확인 항목·완료
  이벤트를 검사한다. 일반/스트리밍 회귀 20개도 모두 모델 생성 없이 처리된다.
- Node 화면 검사 16개를 실행하는 테스트도 전체 pytest에 포함된다.
- 에이전트가 실행 중인 서버·USB Ollama를 직접 조작해 새 질문을
  재실행하지는 않았다. 서버를 중지하거나 자동 재시작하지 않았다.
  아래 사용자 화면 재확인은 별도의 증거로 구분한다.
- 자연어 전반의 의미 검증이나 문서 최신성 판별은 아니다. 지원하지 않는
  표현·혼합 요구는 기존 경로로 넘어갈 수 있다. 새 독립 평가 문항의 사람
  검토가 남으며, 이 10문항의 통과율로 일반 답변 정확도를 보고하지 않는다.

## 사용자 재확인

사용자가 서버 재시작 후 공유한 2·4·6·7·9번 화면에서 포트/화면,
전체 시간 포함, 역할 보존, 연동 추측 방지, USB 질문의 수치표 대체 방지 동작을
확인했다. 이어 공유한 1·3·5·8·10번 화면에서도 역할·API 문서 방식,
성능 비교 한계, 세 모델 모드와 기본 결정, 제한된 요약·전체 검증 현황
미확인 표시를 확인했다. 10번은 상단·하단 두 화면으로 확인했다.

후속 화면 정리에서는 확인된 원문 영역이 없는 구조화 응답에
‘부분 답변’ 대신 ‘근거 부족 · 확인 필요’를 표시한다. 부족 항목 목록과
알려진 안내 꼬리말이 정확히 일치하는 경우에만 본문 중복을 제거한다.
예상하지 못한 추가 문장은 숨기지 않으며 전체 원문은 접힌 영역에 보존한다.
Node 검사 16개 및 전체 pytest 499개가 통과했다. 모의 응답을 쓰는 격리
Chrome에서 새 배지·목록 1회 표시·원문 보존·기존 부분 답변과 모바일을
확인했다. 이후 사용자가 공유한 9번 실제 페이지 화면에서 새 배지와
중복 제거도 재확인했다. 이로써 기존 10문항의 변경 후 화면 확인은 완료했다.
이 문항들은 이미 수정에 사용했으므로 독립 평가 정확도를 뜻하지 않는다.

실행 중인 서버가 자동 새로고침 없이 시작되었다면 해당 PowerShell 창에서
Ctrl+C 후 아래처럼 한 번만 다시 시작한다. USB와 Ollama는 유지한다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

기존 10문항을 다시 입력한다. 2번은 Streamlit 기본 UI, 4번은 두 대상의
전체 시간 포함, 6·7번은 확인된 역할과 미확인 항목 분리, 9번은 엉뚱한
속도표 미표시를 우선 확인한다. 8·10번은 문서 기록의 한계를 함께 확인한다.
