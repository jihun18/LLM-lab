# 부분 답변 표시 개선 — 2026-10-22

## 화면 변경

`privAI.html`의 답변을 한 카드로 묶고 상태·확인한 내용·미확인 항목을 구분했다.

- 기존 제한적 원문 추출 경로가 반환한 답변만 ‘원문에서 확인한 내용’ 영역으로 표시한다. 실제 출처·검사 방식·본문 구분 구조를 함께 확인하며 일반 생성 답변의 문구만 보고 승격하지 않는다.
- `missing_items`를 ‘근거 부족·충돌 항목’으로 별도 표시하고 각 통계·모델·대상과 ‘원문 값 충돌’ 이유를 그대로 보존한다.
- 부분 답변 상단은 ‘부분 답변 · 미확인 항목 있음’, ‘질문 전체가 해결된 것은 아닙니다’로 표시한다. 색뿐 아니라 제목과 문구로도 구분한다.
- 일반 생성 답변은 의미 검토 필요를 유지한다. 수치 자동 대조 성공을 전체 질문 의미 검증으로 표시하지 않는다. 실패 검사는 확인된 내용으로 승격하지 않는다.
- 출처 목록·자동 검사 범위·전체 응답 원문을 네이티브 details/summary로 접고 펼칠 수 있다. 본문 인용도 남기며 원래 응답은 수정하지 않는다. 원문 파일을 열거나 출처 링크를 따라가는 기능을 추가한 것은 아니다.
- 완료 후 카드 상단을 보여 모바일에서도 부분 답변 상태부터 읽을 수 있게 한다. 일반 채팅은 기존 텍스트 표시를 유지한다.

추론·검색·근거 판정 규칙은 바꾸지 않았다. 지원하지 않는 본문 구조는 원래 답변과 부족 항목을 보여주며 임의로 ‘확인한 내용’을 만들지 않는다. 모든 내용은 textContent로 표시해 모델·문서·출처의 HTML을 실행하지 않는다.

## 스트리밍 처리

마지막 NDJSON 이벤트 뒤에 줄바꿈이 없어도 처리한다. 완료 이벤트 없이 연결이 끊기면 요청 실패로 안내하고 성공/부분 완료 카드로 포장하지 않는다. 배열이 아닌 오류·미확인 항목 메타데이터는 안전하게 처리한다. 서버의 알려진 실패 답변 차단 규칙은 그대로다.

## 검증

- 전체 pytest 450개 통과. 신규 Python 테스트는 Node 테스트 실행 래퍼 1개 및 FastAPI/Flask 실제 부분 답변 스트리밍 메타데이터 검사 4개다.
- Node 화면 로직 검사 11개: 부분 추출, 충돌, 실패 검증, 생성 답변의 가짜 제목, 출처/본문 형식 누락, 전체 추출 범위 안내, 수치 검증 한계, 잘못된 배열, HTML 안전, CRLF/전체 원문 보존, 한국어 표시를 검증했다. 이 검사는 Python 래퍼에서도 실행된다.
- headless Chrome의 격리된 API 응답으로 실제 폼 전송·카드 렌더링·출처/원문 펼치기·일반 생성·차단·중단·마지막 줄바꿈 없음·일반 채팅·390px 모바일 레이아웃을 검사했다. 가로 넘침과 화면 오류가 없고 상태 배지가 보임을 확인했다.
- 화면 이미지를 직접 확인했다. 결과는 로컬 `benchmark-results/answer-ui-preview/partial-desktop.png`, `partial-mobile.png`이며 Git에서 제외한다.

브라우저 검증은 목업 API를 사용하는 격리 검증이고, 실제 서버의 USB Ollama 생성을 브라우저에서 호출한 것은 아니다. 별도로 FastAPI/Flask 공통 코어의 실제 부분 답변 NDJSON 계약은 테스트했다. 사용자 서버를 새로 시작하거나 재시작하지 않았다. 서버 실행 중이면 화면 새로고침으로 HTML 변경을 볼 수 있다.

이후 사용자가 실행한 실제 서버에서 [화면→API→Wiki/USB 모델→화면 연결 검증](LIVE-FLOW-VERIFICATION-20261022.md)을 완료했다. 부분 답변·일반 생성·비개인 TXT 업로드와 질문/출처 표시가 통과했고, 테스트 문서는 검색 대상에서 빼서 별도 보관했다. 위 격리 테스트와 별도 결과다.

## 작업 범위

USB 이전으로 저장 공간 문제는 해결되어 모델을 줄이기 위한 A/B 선택 작업은 사용자 요청에 따라 보류했다. 기존 비교 자료는 보존하며 추가 채점·모델 공개·재생성·모델 삭제는 하지 않았다. 이번 변경은 답변 화면 개선에만 한정한다.
