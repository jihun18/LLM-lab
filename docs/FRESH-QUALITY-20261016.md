# 새 질문 품질 평가 — 2026-10-16

## 실행 전 고정 기준

기존 평가와 문장 그대로 중복되지 않는 새 질문 12개를 `fresh_quality_cases.json`에 고정한다. 실제 Wiki 검색 6개와 통제 근거 6개, 충분한 근거/일부 근거/근거 없음 각 4개다. 구현과 과거 실패 유형을 아는 내부 평가이므로 외부 독립 평가나 대표 정확도로 해석하지 않는다. 문장 중복 검사는 의미적 독립성의 증명이 아니다.

이번에는 평가 도구와 문항만 추가한다. 운영 코드·Wiki·기존 문항은 변경하지 않는다. 실행 전후 운영/평가 코드·문항·Wiki 지문을 기록하고, 첫 실행 결과를 본 뒤 기대 표현을 고쳐 통과 수를 올리지 않는다. 후속 개선에 사용한 문항은 개발 회귀 세트로 전환한다.

Wiki는 BM25/top-k 3, 기존 보충 검색을 유지한다. 통제 근거는 가상 도구의 목록을 메모리에서 전달하므로 검색 정확도와 분리한다. 모델 기본값은 qwen3:1.7b다. 오프라인 기본 실행은 모델 호출을 하지 않고 생성이 필요한 문항을 보류한다. 실제 모델 생성은 `--live`로 명시적으로 실행해야 하며 다른 모델 종료·다운로드·서버 재시작·Wiki 자동 기록은 하지 않는다. 단, 실제 Ollama 요청은 서버의 통상 적재 정책에 영향을 받을 수 있으므로 메모리 측정과 동시에 실행하지 않는다.

## 판정 기준

자동 검사는 허용 표현 그룹·금지 표현·출처/인용 연결·차단 여부의 보조 검사다. 자동 통과는 정답이 아니며 자동 불일치도 곧 의미적 오답은 아니다. 모든 답변의 의미 판정은 처음에 미검토다.

- 정답: 요구 전체를 정확한 원문과 연결하고 근거 없는 주장이 없음.
- 부분 답변: 확인한 요구만 답하고 미확인 요구를 명시하며 추측하지 않음.
- 올바른 거절: 답할 근거가 없어 추측하지 않음.
- 잘못된 답변: 역할 교환·수치 대체·오인용·근거 없는 주장 등 내용 오류가 있음.

최종 분류와 별도로 요구 충족(전체/일부/미충족), 근거 오류(있음/없음)를 기록한다. 답할 근거가 있는데 전부 차단한 경우는 안전 여부와 별개로 요구 미충족이며, 올바른 거절로 성공 처리하지 않는다. 미실행·생성 보류·실행 오류는 오답과 섞지 않는다. 판단이 모호하면 메모를 남기고 미검토 상태를 유지한다. 사람 검토 완료 전 전체 의미 정확도나 완료율을 보고하지 않는다.

## 실행

```powershell
.\.venv\Scripts\python.exe fresh_quality.py
# 생성 보류 문항만 첫 실행 보고서에서 확인한 뒤 명시적으로 지정
.\.venv\Scripts\python.exe fresh_quality.py --live --case-ids qXX
```

두 번째 명령의 qXX는 실제 보류 ID로 바꾼다. 문항당 모델 요청 timeout은 90초다. 결과와 검토표는 `benchmark-results/fresh-quality-*.json`, `*.review.md`로 로컬 저장한다. 직접 코어를 호출하므로 실행 중 웹 서버는 필요 없고, 실제 생성에는 Ollama가 필요하다. UI·HTTP·스트리밍 통합 검증을 대신하지 않는다.

## 이번 평가의 범위

첫 결과를 기록하고 우선순위만 정한다. 결과를 보고 운영 코드까지 동시에 수정하지 않는다. 오프라인에서 보류된 문항은 실행 완료로 주장하지 않고, 실제 생성·사람 검토가 끝나야 최종 품질 판단이 가능하다.
