# 복합 질문 근거 확인과 실패 본문 차단

작업일: 2026-10-06

## 수정 전 사용자 화면 비교

사용자가 1.7B·4B·7B 모드에서 같은 질문을 실행한 화면을 제공했다.
단순 역할 비교는 세 모드 모두 원문 추출로 정상 처리됐다. 생성 성능 점수로 세지 않는다.

- 속도 추가: 세 모델 모두 수치 검증 실패였지만 생성 본문이 화면에 그대로 남았다.
- Django 추가: 1.7B는 Flask의 역할을 붙였고, 4B는 근거 부족을 명시했다.
  7B는 답변에 포함하지 않는다고만 해 근거 부족 설명이 불충분했다.
- 함께 쓰는 이유: 1.7B는 속도 설명으로 벗어났고, 4B·7B는 역할 분담을 설명했으나
  실제 연동이나 공모전 활용까지 선택 출처가 뒷받침하는지는 별도 검토가 필요했다.

이는 소수 개발 질문의 수동 관찰이며 독립 평가 점수나 모델 우열의 확정 근거가 아니다.

## 변경

영문 대상명이 명시되고 검색 근거의 역할 표·명시적 역할 목록에 둘 이상의 대상이
일치하는 프로젝트 역할 질문에만 요구 확인을 적용한다.

1. 요청 대상 모두의 명시적 역할 근거를 확인한다. 이름만 언급된 문서는 역할 근거로 보지 않는다.
2. 속도 추가 요구에는 각 대상 행과 생성속도 열이 있는 표를 요구한다.
3. 이유 요구에는 요청 대상들이 함께 등장하고 이유·목적·분담 표현이 있는 문장을 요구한다.
   역할 표만으로 실제 연동 이유를 추측하지 않는다.
4. 부족한 항목은 생성 전 명시한다. 확인한 범위는 현재 검색 결과이며 Wiki 전체에 없다는 뜻이 아니다.
5. 생성 후에도 선택 출처의 항목 근거와 답변의 대상·속도 단위·이유 표현 누락을 확인한다.
6. 알려진 검증 실패는 생성 본문을 안전한 안내로 바꾼다. JSON 및 스트리밍에 거절된 답변
   본문을 별도 필드로 보내지 않는다. 검증 사유와 검색 근거는 진단용으로 유지한다.

`answer_status`는 생성 결과에 blocked/review_required/verified로 부여한다.
기존 원문 추출 경로는 자체 실행 경로와 검증 상태를 유지한다.
속도 원문 추출기가 복합 질문의 역할 요구를 무시하지 않도록 해당 질문을 제외한다.

## 검증과 한계

12개 회귀 테스트를 추가해 전체 146개가 통과했다. 실제 Wiki BM25 검색으로 사용자의
세 복합 질문이 생성 전에 부족 항목을 안내하는지 확인했다. 임의 도구 표에서도 근거가
충분할 때 생성 경로를 유지하고, 선택 출처 부족·답변 이유 누락·실패 본문의 JSON 및
스트리밍 노출 차단을 확인했다.

보수적인 제한 규칙이므로 의역·여러 문장에 분산된 이유·한글 대상명은 충분히 처리하지
못할 수 있다. 이유 표현이나 대상명이 존재한다고 의미 정확성이 증명되는 것은 아니다.
원문에 없는 기능 한계 등 자유 서술은 여전히 사람 의미 검토가 필요하다.
검색에서 필요한 속도 표를 놓친 경우도 근거 부족으로 안내한다. 후속 과제는 항목별
검색 보완과 주장별 근거 연결이며, 이번 질문들은 개발 회귀 세트로만 사용한다.

## 재시작 후 실제 화면 확인

빠른 모드·BM25에서 Django·속도·함께 쓰는 이유의 세 질문 모두 부족 항목을 명시했다.
단순 역할·차이 질문은 기존 비교표 원문 추출과 정확한 출처를 유지했다.
각 스트리밍 요청은 HTTP 200이며 브라우저 콘솔 오류는 없었다.
이 세 복합 질문은 생성 전 거절 경로이므로 수정 후 모델 생성 정확도 향상으로 세지 않는다.
생성된 실패 답변의 본문 차단은 자동 테스트로 확인했으며, 실제 Ollama에서 의도적으로
실패 답변을 유도하는 추가 실험은 이번 확인 범위에 포함하지 않았다.
