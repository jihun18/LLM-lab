# 복합 질문 별도 첫 평가

평가일: 2026-10-06

## 평가 목적과 고정 조건

추가 검색 개선에 사용한 질문을 반복하는 대신 새 질문 12개를 실행했다.
질문과 요구 문자열·금지 값·기대 출처·부분 답변 상태는 실행 전에
`compound_holdout_cases.json`에 작성했다. 결과를 본 뒤 생산 코드를 수정하지 않았다.
운영 코드 기준은 추가 검색 개선 커밋 `6446d08`이다.

평가자가 구현을 알고 만든 소규모 별도 확인 세트다. 완전히 독립적인 외부 평가나
대표 표본 정확도를 의미하지 않는다. 이번 결과를 보고 튜닝에 사용하면 다음부터
이 질문들은 개발 회귀 세트로 분류해야 한다.

- Wiki 6문항: 기존에 사용하지 않은 대상 조합·미등록 대상·의역·미래 연도 질문
- 통제 근거 6문항: 상충 속도·상충 역할·명시적 이유·속도 부재·이름만 언급·연도별 행 충돌
- 실제 검색: BM25, top-k 3, 기존 제한된 추가 검색 설정 유지
- 통제 사례: 가상의 근거를 메모리에서 전달. 실제 Wiki나 업로드 문서에 삽입하지 않음
- 출력: 로컬 `benchmark-results/` JSON, 문항·코드·Wiki 파일 SHA-256 포함
- 모델: 자동 추출은 모델 호출 없음. 의역 질문 h05만 실제 qwen3:1.7b 생성

## 실행

```powershell
python compound_holdout.py
python compound_holdout.py --live --case-ids h05
```

첫 명령은 실제 모델 호출이 필요하면 `pending_generation`으로 남긴다.
모의 생성 답변을 만들어 통과시키지 않는다. `--live`는 필요한 문항에만 실제 Ollama를
호출하며, 제한 시간은 요청당 90초다. 두 번째 명령은 보류 문항만 실행한다.

## 첫 결과

| 구분 | 항목 검사 통과 | 미충족 | 첫 실행 보류 |
|---|---:|---:|---:|
| Wiki 6문항, 모델 없는 실행 | 5 | 0 | 1 |
| 통제 근거 6문항 | 6 | 0 | 0 |
| 보류 h05 실제 모델 실행 | 0 | 1 | 0 |

따라서 서로 다른 12문항 중 자동 항목 검사 통과 11개, 답변 요구 미충족 1개다.
Wiki 최종 결과는 5/6, 통제 근거 정책 결과는 6/6으로 분리한다.
이를 1.7B 정확도 91.7%나 일반 RAG 검색 정확도라고 보고하지 않는다.
11개의 성공은 모델 호출 없는 경로이며 통제 사례는 검색 정확도 평가가 아니다.

## 발견한 한계

h05: `Flask와 Streamlit은 무엇을 담당하며 응답 속도는 어때?`

질문에 `역할` 또는 `용도`가 없어 제한된 요구 분석 경로가 작동하지 않았다.
추가 검색 기록은 빈 목록이었다. 실제 모델 생성은 34.842초였고, 선택한 근거 절에
요청 단위의 표가 없다는 이유로 검증 실패했다. 본문은 안전한 안내로 차단됐다.
요구한 값과 실측 절 출처가 표시되지 않아 답변 완료 기준에서는 실패다.
차단된 답변에는 인용이 없고 검색 절은 진단용으로 남아 있으므로 인용·표시 근거
일치 검사도 실패했다. 이 항목을 출처 문자열을 지어냈다는 증거로 해석하지 않는다.
거절된 생성 본문은 보존하지 않아 의미 오류의 구체적인 내용은 확정하지 않는다.

통제 근거에서는 이름만 있는 미등록 대상의 역할을 만들지 않았고, 서로 다른 값이나
연도별 행을 임의로 고르지 않았다. 명시된 이유 문장은 복사했다. 이유 문장의 의미
정확성까지 자동으로 검증했다는 뜻은 아니다.

## 다음 단계

의역한 역할 표현을 인식하는 범위를 늘리되, 응답속도와 모델 생성속도의 의미 차이를
명시해야 한다. 먼저 h05를 실패 회귀 사례로 전환하고 수정 후 확인한다.
그 수정의 평가에는 다시 별도의 새 질문을 사용한다. 이번 턴에는 생산 코드를 수정하지 않았다.

평가 도구 자체의 출처 절 대조·누락·금지 값·오프라인 보류·의미 검토 분리 검사를
추가해 전체 자동 테스트는 164개가 통과했다. 이는 평가 도구 회귀 테스트 수이며
12문항 평가 결과와 별개다.

## 평가 이후 개선과 회귀 전환

첫 평가 기록을 `c153dbf`로 커밋한 다음 운영 코드를 수정했다.
`무엇을 담당`, `담당하는 일`, `어떤 일을`을 제한적으로 역할 요청으로 인식한다.
추가 요구를 버리지 않도록 기존 제한 문법을 유지한다.

h05는 추가 검색과 원문 복사 경로로 처리되며 모델을 호출하지 않는다.
두 역할과 과거 생성속도 행을 찾지만, 전체 응답속도의 동일 조건 비교 근거는 없으므로
`partial` 상태로 남긴다. 모델 적재·입력 처리·답변 길이를 포함하는 전체 응답시간과
token/s의 차이를 안내한다. 응답속도 요청의 완전 해결로 해석하지 않는다.

원래 문항과 자동 검사 기준은 변경하지 않았다. 재실행 파일
`compound-holdout-20261006-163232.json`에서는 자동 항목 검사 12/12가 통과했다.
이 검사는 h05의 키워드·출처가 표시됐다는 뜻이며 사람 의미 검토는 여전히 필요하다.
이번 결과는 수정에 사용한 회귀 세트 결과다. 첫 별도 평가의 11/12 결과를 대체하거나
새로운 독립 정확도 향상으로 제시하지 않는다. 다음 평가는 다시 새로운 질문이 필요하다.
추가 11개 자동 테스트를 포함해 전체 175개가 통과했다.

재시작 후 실제 빠른 모드·BM25 화면에서도 h05의 역할·실측 행·출처와
전체 응답속도 비교 근거 부족 안내 및 부분 추출 상태를 확인했다.
스트리밍 요청 HTTP 200, 브라우저 콘솔 오류는 없었다.

사용자도 같은 의역 질문의 응답 본문을 제공해 후속 확인했다. Flask·Streamlit 역할과
당시 모델 qwen3:1.7b의 실측 행·절별 출처, 생성속도와 전체 응답속도의 구분,
동일 조건 비교 근거 부족 안내 및 부분 추출 상태가 모두 표시됐다.
이는 h05 개발 회귀 확인이며 새로운 독립 평가나 응답속도 비교의 완전 해결이 아니다.
