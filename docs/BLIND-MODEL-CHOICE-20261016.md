# 4B·7B 개인용 모델 선택 비교

## 실행 전 기준

1.7B는 빠른 모델로 유지한다. 설치된 `qwen3:4b-instruct`와 `qwen2.5:7b-instruct`를 새 12문항으로 한 차례 비교한다. 실제 설치 정보는 둘 다 GGUF/Q4_K_M이고 약 2.50GB/4.68GB, 각각 Qwen3 4.0B/Qwen2.5 7.6B다. 같은 양자화지만 모델 계열도 달라 크기만의 인과 실험이 아니다. USB의 모델은 삭제하지 않는다.

문항 파일은 실행 전 커밋으로 고정한다. Wiki 복합 질문 4개, 제공 문서 요약 4개, 실제 글쓰기·추론 4개다. Wiki의 지정 절을 한 번 읽어 같은 입력으로 고정하므로 검색 정확도 평가가 아니다. 다른 문항은 동일한 짧은 자료를 제공한다. 운영 RAG의 표 추출·안전 거절 경로를 사용하지 않고 API로 직접 생성하므로 공통 코드 응답이 모델 품질에 섞이지 않는다. 이 결과는 앱 전체 안전성 평가를 대신하지 않는다.

## 동일 조건과 제한

- 시스템 문구·실제 사용자 입력 SHA-256 동일, think=false
- num_ctx=2048, num_predict=256, temperature=0.3, seed=42
- 문항당 timeout 180초, 응답마다 체크포인트, 자동 재시도 없음
- 적재 횟수를 줄이기 위해 모델별 12개를 연속 실행하며 실행 순서 효과는 완전히 통제하지 않음
- 실제 Ollama 버전·설치 digest/양자화/크기·USB 모델 경로·입력·출력·적재/입력 처리/생성 경과를 별도 공개 파일에 보존
- 잘림·빈 답변·다른 모델·문맥 예산 초과·모델명 자기 노출을 별도 표시하며 정상 완료 쌍으로 속이지 않음
- 콜드 상태를 강제하거나 다른 모델을 명시적으로 종료/삭제하지 않음. Ollama 자체 적재 정책은 적용됨
- USB·캐시·CPU 부하·답변 길이가 달라 단일 실행을 보편적인 순위나 순수 생성속도 차이로 해석하지 않음

## 블라인드 검토와 결정

문항마다 A/B 대응을 바꾸되 각 모델이 A인 문항을 6개씩 배정한다. 대응은 생성 전에 고정하고 답변 내용에 따라 바꾸지 않는다. `blind-review.md`에는 모델명·시간·용량을 넣지 않는다. `reveal-private.json`에는 전체 원자료와 대응을 보존하므로 품질 판정 전에 열지 않는다. 같은 폴더의 분리 파일일 뿐 암호화/접근 통제는 아니며 사용자가 내용을 보면 블라인드가 해제된다.

사용자가 정확성·요구 충족·명료성 각 0~2점과 중대 오류를 확인하고 A/B/동점/보류를 기록한다. 자료와 확인 기준을 함께 제공한다. 잘림이나 실행 실패가 있으면 별도 보류한다. 사람 판정 전 모델을 추천하거나 자동 문자열 점수를 품질로 대신하지 않는다.

**개인 선택 규칙:** 7B가 12개 중 8개 이상 우세, 중요 6개 중 4개 이상 우세, 중대 오류가 더 많지 않으며 사용자가 속도를 수용하면 7B를 우선한다. 품질이 비슷하면 4B를 우선한다. 이는 통계적 유의성 기준이 아니라 선택을 명확히 하기 위한 사전 정책이다. 애매한 문항만 별도 재확인하고 비교를 계속 확대하지 않는다. 어느 모델도 자동 삭제하지 않는다.

```powershell
.\.venv\Scripts\python.exe blind_choice.py
.\.venv\Scripts\python.exe blind_choice.py --run
```

첫 명령은 계획만 확인하고 모델을 호출하지 않는다. 두 번째는 실제 생성 24개를 실행하며 USB와 Ollama 서버를 유지해야 한다. 결과는 Git에서 제외된 `benchmark-results/blind-choice-.../`에 저장한다.
