# 제한적 Wiki 원문 추출

구현·확인일: 2026-10-06

## 목적과 적용 범위

1.7B가 Flask와 Streamlit 역할을 바꾸거나 상태 문구를 빠뜨리는 경우가 있었다.
원문에 명시된 좁은 목록 질문에는 LLM 생성 대신 직접 추출하도록 했다.

- 역할: 검색 1위 원문의 `- 역할: **대상**` 목록에 질문에서 명시한 대상이 두 개 이상 존재할 때 대상·역할 쌍을 그대로 표시한다.
- 상태 문구: 개수와 상태 문구를 요청하고, 검색 1위 절 제목의 단어가 질문에 있으며, 백틱 불릿 목록 개수가 요청과 일치할 때 원문 항목을 전부 표시한다.
- 사용한 1개 절만 출처로 표시한다. 모델 선택과 무관하게 동일한 원문을 반환한다.
- 화면 검증 이름은 `역할·문구 원문 추출 완료`다. 원문 복사 여부만 보장하며 원문 자체의 사실성·최신성은 보장하지 않는다.

비교·이유·예시·수치 등 추가 요구를 감지하거나, 알려지지 않은 영문 도구명·충돌하는 명시적 역할 쌍·요청 개수 불일치가 있으면 추출하지 않는다.
검색 1위가 다른 형태의 절이면 낮은 순위의 편리한 목록을 임의로 대신 쓰지 않는다.
이때 기존 생성·검증 경로를 사용한다. 복잡한 의도 전체를 판별하는 기능은 아니며,
새로운 표현이나 한글 도구명 등 아직 검사하지 못하는 요청은 후속 평가가 필요하다.

기본 검색 BM25, 기본 생성 모델 1.7B, 전체 근거 full 정책은 변경하지 않았다.
FastAPI·Flask·Streamlit이 공유하는 RAG 서비스에 적용했다. Wiki 근거를 끈 일반 채팅은 해당하지 않는다.

## 실제 확인 결과

BM25 검색부터 응답까지 현재 Wiki로 확인했으며, 모델 호출 시 실패하는 점검용 클라이언트를 사용해 생성 호출이 없음을 확인했다.

| 질문 | 결과 | 서비스 처리 시간 |
|---|---|---:|
| FastAPI·Flask·Streamlit 각각의 용도 | 원문 3쌍과 출처 표시 | 0.002초 |
| 화면에 나타나는 네 가지 상태 문구 | 원문 4항목과 출처 표시 | 0.004초 |
| 검증 화면의 상태 문구 4가지 그대로 적기 | 원문 4항목과 출처 표시 | 0.001초 |

각 질문 1회인 로컬 기능 점검이다. 브라우저 전송·초기 색인 시간을 포함한 체감 시간이나
LLM 생성속도·일반 사실 정확도 측정이 아니다. `tokens_per_second`는 null,
`model`은 `deterministic-text`, `execution_path`는 `deterministic_text`로 분리한다.

보고서: 로컬 `benchmark-results/source-extraction-20261006-114016.json`.
전체 자동 테스트는 **100개 통과**했다. 실제 Wiki 검색·공유 스트림과 FastAPI/Flask의
JSON·스트리밍 API를 모델 호출 없이 확인했다. Streamlit 화면을 실제 브라우저에서 조작한 검증은 하지 않았다.

## 평가 도구와 다음 확인

`model_comparison.py`는 원문 추출을 별도 경로로 분류해 모델 생성 시간 평균에서 제외한다.
LLM의 full/primary 자체 비교 도구 `context_comparison.py`는 명시적으로 원문 추출을 끄며,
모델 답변 비교와 원문 추출 효과를 혼동하지 않도록 기록한다.

```powershell
python source_extraction_check.py
python -m pytest -q
```

실행 중인 웹 서버는 이번 작업에서 재시작하지 않았다. 반영하려면 서버 터미널에서
Ctrl+C 후 기존 실행 명령으로 다시 시작하고 브라우저를 새로고침한다. Wiki 근거 사용을
켠 상태에서 위 두 원래 질문을 넣어 역할 연결과 네 항목·출처를 확인한다.

다음에는 아직 지원하지 않는 역할 질문 표현, 복합 요구, 충돌 문서 및 원문 변경을
추가 평가한다. 질문이 불명확할 때 일부만 답하지 않는지와 사람 검토가 핵심이다.
