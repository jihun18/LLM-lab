## 웹 프레임워크 비교

공통 질문:

```text
경량 LLM의 장점을 한국어로 두 문장만 설명해줘.
```

| 프레임워크 | 모델 | 전체 시간 | 생성속도 |
|---|---|---:|---:|
| FastAPI | qwen3:1.7b | 13.975초 | 11.75 token/s |
| Flask | qwen3:1.7b | 5.003초 | 12.61 token/s |
| Streamlit | qwen3:1.7b | 4.953초 | 11.24 token/s |

전체 시간은 최초 모델 적재, 답변 길이와 캐시 상태의 영향을 받는다. 실제 생성속도는 약 11~12 token/s로 유사하므로 위 표만으로 Flask나 Streamlit이 추론 자체에서 더 빠르다고 결론 내리지 않는다.

결론:

- FastAPI: 정식 REST API와 입력 검증
- Flask: 최소 구현과 원리 학습
- Streamlit: 빠른 실험 UI

## 모델 비교 — 5문항 자동 평가

문항 유형:

1. 한국어 두 문장 설명
2. 정확히 세 항목 생성
3. 주어진 글 요약
4. REST API 기초 설명
5. 간단한 수리 추론

| 모델 | 평균 시간 | 평균 token/s | 평균 자동점수 |
|---|---:|---:|---:|
| qwen3:0.6b | 2.814초 | 24.45 | 80.0 |
| qwen3:1.7b | 7.205초 | 10.28 | 80.0 |
| qwen3:4b-instruct | 16.038초 | 5.00 | 83.3 |

자동점수는 한국어 비율, 문장·목록 개수와 필수 핵심어를 확인한다. 사실성 점수가 아니다.

### 사람 검토에서 발견한 오류

- 0.6B가 경량 모델의 메모리 장점을 잘못 설명
- 0.6B가 `42초 = 0.7초`라는 잘못된 계산을 추가
- 0.6B가 프롬프트 일부를 답변에 반복
- 1.7B가 경량 모델이 메모리에 데이터를 저장한다는 부정확한 설명 생성
- 1.7B가 GET 요청은 데이터를 전송하지 않는다고 과도하게 단순화
- 1.7B는 주어진 글 요약과 `7 × 6 = 42초` 계산에서 상대적으로 안정적
- 4B Instruct가 두 문장 요구에 한 문장만 출력
- 4B Instruct가 `개인정보` 대신 `사용자 데이터`를 사용해 필수 핵심어 일부 누락
- 4B Instruct의 한국어 요약은 자연스러웠지만 `privAI`, `API`, `Ollama`, `PC` 때문에
  단순 문자 비율 평가에서 한국어 조건 실패
- 4B Instruct가 GET은 데이터를 전달하지 않고 POST는 더 안전하며 캐시되지 않는다고
  과도하게 일반화
- 4B Instruct의 `7 × 6 = 42초` 계산은 정확했으나 결과를 두 번 반복

## RAG 오류와 개선

### 표 열 혼동

질문이 평균 `속도`를 요구했지만 1.7B가 평균 `시간` 열의 2.814초와 7.205초를 답했다.

개선:

- Markdown 표 구조 파싱
- 질문 단위와 열 이름 대응
- 속도는 token/s, 시간은 초 열 사용
- 확정 가능한 표 값은 LLM 호출 생략

개선 후 답:

- qwen3:0.6b — 24.45 token/s
- qwen3:1.7b — 10.28 token/s

### 업로드 정책 문서

가상 문서의 지원금과 마감일을 질의했다.

- 월 10만원
- 2026년 9월 30일
- 업로드 Markdown 출처 선택 성공
- 금액·날짜 원문 대조 성공
- 상대 점수 필터 적용 후 관계없는 보조 출처 제거

## 해석

1. 속도만 보면 0.6B가 개발 루프에 유리하다.
2. 사실성과 지시 준수는 모델 크기만으로 보장되지 않는다.
3. 1.7B도 자체 지식에 맡기면 오류가 발생한다.
4. RAG는 올바른 문서를 찾더라도 표 해석 오류를 완전히 막지 못한다.
5. 결정론적 검증 하니스가 수치형 질문의 신뢰도와 속도를 동시에 개선한다.
6. 4B는 자동점수가 소폭 높지만 응답시간이 늘었고 사실 오류가 사라지지는 않았다.
7. 영문 제품명이 필수인 한국어 문항에서는 단순 한글 비율 점수가 실제 품질을
   낮게 평가할 수 있다.

## 7B 한계 시험

`qwen2.5:7b-instruct` Q4_K_M을 첫 문항 하나로 시험했다.

- 전체 시간: 117.257초
- 생성속도: 3.16 token/s
- 생성 토큰: 126
- 최초 자동점수: 100.0
- 평가기 수정 후 점수: 66.7

답변에 긴 중국어 해설이 포함됐지만 기존 `korean_ratio`가 한자를 무시하여 한국어로
오판했다. 모든 문자권의 알파벳 문자를 분모에 포함하도록 수정한 뒤 한국어 비율은
0.503으로 측정됐다. 7B는 실행에는 성공했지만 응답시간과 언어 지시 준수 기준을
통과하지 못해 전체 5문항 평가는 생략했다.

## 4B FastAPI RAG 시험

4B Instruct를 FastAPI 화면에서 선택하고 Wiki를 재색인한 뒤 실제 문서 질문을 시험했다.

- 4B 평균 생성속도: `5.00 token/s`를 표에서 즉시 조회하고 검증 통과
- 7B 평가 생략 이유: 응답시간과 언어 지시 준수 미달을 정확히 설명하고 출처 연결
- 생성형 이유 답변: 69.588초, 4.05 token/s

시험 중 `평균 속도` 열을 인식하지 못해 웹 프레임워크 표를 잘못 선택하는 오류를
발견했다. 속도 열 이름과 질문의 모델 식별자를 함께 반영하도록 표 추출기를 수정했다.
복합질문은 단일 수치 자동답변으로 축소하지 않도록 제한했다.
