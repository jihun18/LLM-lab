# 업무와 대상별 메모리 요구의 제한적 처리

작업일: 2026-10-06. 수정 전 실제 평가 기록은 `e2fb51c`로 먼저 커밋했다.

## 변경 범위

- `업무`를 역할 요청 표현으로 인식한다. 기존 두 대상 이상 근거 조건은 유지한다.
- `- Flask: 최소 구현 비교`처럼 영문 대상명과 역할이 한 줄인 목록을 제한적으로 인식한다.
  API/UI/백엔드/구현/화면 등 역할 신호가 없는 이름 메모·숫자만 있는 줄은 제외한다.
- 원문 복사에서 명시적 비교표가 있으면 그 역할 셀을 우선한다. 표가 없을 때 일반 목록을
  사용하며 목록 값끼리 충돌하면 임의 선택하지 않는다. 표와 서술 목록 사이의 모든
  의미 모순을 검사하는 기능은 아니다.
- 메모리 요구는 별도 항목으로 추적한다. 해당 대상 이름과 메모리 사용량·RSS·RAM 사용
  열이 있는 표 및 MB/GB 등 단위의 측정 행만 복사한다. 함께 기록된 조건 열도 유지한다.
- 근거가 없으면 대상별 부족 항목으로 안내하고 부분 답변으로 표시한다. 대상이 아닌
  PC RAM 용량·모델 파일 크기·생성속도를 메모리 사용량으로 대체하지 않는다.
- 메모리 보충 검색도 기존 총 4개 질의·추가 6개 조각 제한과 검색 모드를 유지한다.
  검증용 측정 표를 실제 Wiki에 새로 넣거나 결과를 지어내지 않았다.

## 검증

7개 테스트 추가와 기존 메모리 제외 테스트의 지원 범위 갱신으로 전체 182개가 통과했다.
업무·응답속도와 역할 의역·메모리 질문은 실제 Wiki에서 모델 호출 없는 부분 답변 경로로
처리된다. 역할과 과거 생성 기록을 보여주되 응답속도 동일 조건 비교는 미확인으로 남는다.
메모리 질문은 역할만 답하고 두 도구의 메모리 측정 근거 부족을 명시한다.

가상 근거로 숫자 메모의 역할 오인 방지, 대상별 측정 행·모델 조건 유지, 상충 측정 값과
상충 일반 역할 목록 미선택을 확인했다. 이는 개발 회귀 확인이며 새 독립 평가가 아니다.
기존 실패 두 문항은 이제 회귀 세트로 전환하며 최초 실제 생성 실패 결과를 덮어쓰지 않는다.

서비스 재실행 기록은 `benchmark-results/role-phrase-live-20261006-171515.json`에
저장했다(로컬 평가 산출물, 커밋 제외). 두 문항 모두
`deterministic_requirement_copy` 경로이고 생성 토큰 수는 0이었다.
서버 재시작 후 브라우저에서도 두 질문을 전송하여 역할·출처와 미확인 항목이
표시되는 것을 확인했다. 두 스트리밍 요청은 HTTP 200이며 브라우저 콘솔 오류는 없었다.
메모리 질문에는 생성속도 숫자가 없고 두 대상의 측정 근거 부족이 표시됐다.

## 한계와 다음 평가

단순 문법·형식 검사다. 모든 업무 의역·한글 대상명·메모리 표 단위·대상 범위를 지원하지
않고, 측정 조건의 공정성이나 원문 자체의 사실성도 보장하지 않는다.
명시적 표 우선순위는 문서 간 의미 충돌의 해결을 뜻하지 않는다.
다음에는 이번 개선에 사용하지 않은 질문으로 형식과 조건 경계를 따로 평가한다.
