# RAG 근거 길이 비교 실험

실행일: 2026-10-06. 기존 수정 후 비교의 고정 검색 결과를 사용한다.
검색 순위·질문·생성 한도는 바꾸지 않고 생성 모델에 보내는 근거 묶음만 비교한다.

## 방법

- full: 기존 검색된 근거를 모두 전달한다.
- primary: 1위 근거의 본문 전체를 전달한다. 문장·목록·표를 자르거나 요약하지 않는다.
- 질문의 명시적 연도·모델 태그가 1위에 없으면 전체 근거로 되돌린다.
- 실제 전달한 근거만 허용 출처·표시 출처·수치 검증에 사용한다.
- 1.7B와 Q4_K_M 7B에서 같은 4문항을 순차 비교한다.
- 질문마다 두 방식의 순서를 교대로 바꾼다. 매 측정 전에 대상 모델을 내리고 다른
  짧은 인사로 적재한다. 이 적재 시간은 제외하며 동일 평가 프롬프트로 예열하지 않는다.
- 컨텍스트2048, 최대생성256, temperature0.3, seed42 및 동일 시스템 지시를 유지한다.

측정 대상은 모드 태그·프레임워크 역할·검증 상태·중복 업로드다. 모두 실제 생성
경로이며 표 추출·거절을 평균에 섞지 않는다. 원본 비교 JSON의 검색 결과를 읽으므로
이번 답변 시간에는 검색시간이 없다. 입력 토큰 수·입력 처리 시간·생성 시간·자동 점수와
원문 대조를 함께 확인한다. 한 번씩 비교한 작은 내부 실험이다.

## 측정 결과

| 모델·근거 | 입력 토큰 평균 | 입력 처리 평균 | 전체 답변 평균 | 자동 점수 평균 |
|---|---:|---:|---:|---:|
| 1.7B·full | 834.8 | 14.957초 | 28.517초 | 100.0 |
| 1.7B·primary | 537.0 | 8.716초 | 14.936초 | 98.5 |
| 7B Q4_K_M·full | 823.8 | 59.699초 | 71.441초 | 100.0 |
| 7B Q4_K_M·primary | 526.0 | 36.083초 | 48.070초 | 100.0 |

모델별4문항 × 2방식, 총16개 생성 응답을 완료했다. 평균 답변시간은 1.7B에서
약47.6%, 7B에서 약32.7% 감소했다. 이는 같은 실행의 full/primary 비교일 뿐이며
사용자 앱 전체 시간이나 반복 측정으로 확정한 성능 개선율이 아니다.
근거 토큰 감소는 입력 처리시간 감소로 이어졌지만 생성 길이·내용도 달라져
전체 시간 차이를 입력 감소의 효과 하나로만 해석할 수는 없다.

## 원문 대조 결과 — AI 검토

| 문항 | 1.7B·full | 1.7B·primary | 7B·full/primary |
|---|---|---|---|
| 두 모드의 태그 | 두 태그 정확·설명 중복 | 두 태그 정확·출처 중복 | 둘 다 정확 |
| 프레임워크 역할 | FastAPI에 시연 역할을 잘못 추가 | Flask와 Streamlit 역할을 서로 바꿈 | 둘 다 역할 정확 |
| 네 가지 검증 상태 | 4개 의미 유지·출처 문구 한 글자 깨짐 | 사람 의미 검토 상태 누락 | 둘 다4개 정확 |
| 중복 업로드 | 파일명·크기·확장자 비교를 중복 기준처럼 추가 | 일반 업로드 검증을 중복 기준에 혼합 | 둘 다SHA-256 기준 설명 |

1.7B의 full 방식도 오류가 있었다. 이전 세 모델 실행에서는 역할을 정확히 답했지만
이번 측정에서는 틀렸다. 같은 seed와 근거만으로 동일 응답·사실성 안정성을 보장하지
않으며 실행·프롬프트 캐시 등의 조건이 영향을 줄 수 있다. 원인은 이 실험만으로
단정하지 않는다. 자동 점수100은 역할별 대응이나 잘못 추가한 조건을 잡지 못했다.

primary에서는 1위 본문을 원문 그대로 유지했고 필요한 역할·네 번째 검증 상태·해시
조건도 들어 있었다. 따라서 여기서 보인 오류는 필요한 문자열을 전처리로 잘라낸
것이 아니라 모델 출력에서 나타난 오류다. 축약이 모든 오류의 원인이라는 주장도
하지 않는다. 사람의 의미 검토는 아직 완료하지 않았다.

판정: 속도 감소는 관찰됐지만 **1.7B 기본 축약 적용은 보류**한다. 7B는 이번
4문항에서 내용 보존과 속도 감소를 확인한 실험 후보일 뿐, 다른 질문의 안전성을
검증한 제품 기본값이 아니다. 앱 기본은full로 유지한다.
다음은 역할 대응·필수 목록 항목의 자동 검증을 강화한 뒤 축약 실험을 반복하는 것이다.

원본: 로컬 `benchmark-results/context-comparison-20261006-105014.json` 및 `.review.md`.
채점표에서는 같은 질문의full/primary를 별도 표시하고 사람 평가 칸은 유지한다.

## 안전성 한계와 적용 범위

1위 본문을 보존해도 2·3위에만 있는 정보는 없어질 수 있다. 명시적 연도·모델
보존만으로 복합질문의 모든 조건이 보존됐다고 보장할 수 없다. 단독 근거로 충분한
질문인지 판별하는 검증과 추가 실패·복합질문 평가가 필요하다.
따라서 이번 후보는 `grounded_response(..., context_mode="primary")`의 실험 옵션이다.
실행 중인 앱과 API의 기본값은 **full**로 유지한다. 실험에서 빠르다는 이유만으로
모든 질문의 기본값을 바꾸지 않는다. 결정론적 표 추출은 기존 전체 근거를 그대로 사용한다.

## 실행

### 역할·목록 프롬프트 보강 후 재실험 (2026-10-06)

1.7B만 역할 질문과 네 가지 상태 문구 질문을 full/primary 각각 한 번씩 다시 생성했다.
검색 스냅샷·seed 42·2,048 컨텍스트·최대 출력 256을 유지했으며, 매번 짧은 인사로 모델만 예열했다.
이번에도 검색 시간과 모델 예열 시간은 응답 시간에서 제외한다.

| 질문 | full | primary |
|---|---|---|
| 프레임워크 역할 | 23.793초, 연결 관계 적절 | 14.742초, Flask·Streamlit 역할 교환 |
| 네 가지 상태 문구 | 24.548초, 네 문구 존재 | 15.364초, 네 문구 존재 |

내용 판정은 **AI 원문 대조**이며 사람 검토를 완료했다고 표현하지 않는다.
full 평균 24.171초, primary 평균 15.053초였지만 2문항 각 1회뿐이다.
이전 4문항 평균과 직접 비교해 성능 개선을 주장하지 않는다. 상태 문구 결과는 이번에는
개선됐지만 축약 역할 오류가 남았으므로 **기본 full 유지**다.

재실험 중 올바른 full 역할 답변을 검증기가 잘못 경고했다. 쉼표로 연결된 다음 구절의
역할을 앞선 도구에 붙인 문제였다. 구절 경계를 보강하고 역할 설명이 다음 대상 앞에
오는 표현은 보수적으로 판정을 유보하도록 수정했다. 실제 문장을 회귀 테스트에 추가해
전체 78개 테스트가 통과했다. 수정 후 재검사에서 full 역할 답변의 오경고는 사라지고
primary의 실제 역할 교환은 검출됐다. 이는 규칙 오류 수정이며 새 생성 결과가 아니다.

원본 보고서: `context-comparison-20261006-113132.json`.
별도 재검사: `context-comparison-20261006-113132-rechecked.json`.
원본 자동점수(full/primary 모두 평균 87.5)는 수정 전 오경고를 포함하므로 최종 품질
지표로 사용하지 않는다. 원본은 그대로 보존하고 수정 후 검증 결과를 별도 기록했다.

```powershell
python context_comparison.py --snapshot benchmark-results/model-comparison-20261006-103531.json --models qwen3:1.7b --case-ids fresh_roles fresh_badges
```

이번 실험은 현재 Python 서비스 코드를 직접 호출했다. 실행 중인 웹 서버는 재시작하지 않았다.
다음 후보는 명시적 역할·문구 복사 질문의 제한적 원문 추출이다. 일반 요약까지 자동 추출로
바꾸지 않고, 새 표현의 질문과 사람 검토로 먼저 확인해야 한다.

### 전체 비교 실행

```powershell
python context_comparison.py --snapshot benchmark-results/model-comparison-20261006-103531.json
```

결과는 로컬 `benchmark-results/context-comparison-시각.json`과 `.review.md`에 남긴다.
다른 snapshot으로 시험하려면 같은 질문 ID와 근거 구조가 들어 있는 파일을 지정한다.
각 측정마다 저장해 중단된 경우 완료된 답변과 오류를 확인할 수 있다.

이전 세 모델 비교는 첫 문항에 동일 프롬프트 캐시가 작용했고, 이번은 짧은 인사만으로
예열했다. 이전 평균과 이번 평균을 직접 비교하지 않고 **이번 full/primary 쌍**을 비교한다.
