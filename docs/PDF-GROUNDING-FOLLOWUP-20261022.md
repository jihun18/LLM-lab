# 실제 업로드 PDF 후속 개선 — 2026-10-22

## 범위와 발견

사용자가 업로드한 해커톤 요강의 5문항 화면에서 1·2·4번의 답변 차단,
3번의 잘못된 시상 인원·금액 표시, 5번의 미확인 호출 한도 안내 실패를 확인했다.
이 문항들은 이제 개발 회귀이며 독립적인 정확도 평가로 보고하지 않는다.
요강의 최신 공지·행사 운영 여부·법적 효력을 조사한 것이 아니다.

에이전트의 분리 실험 중 원본 PDF와 기존 업로드 Markdown은 변경하지 않았다. 원본을 별도 실험 공간에서
다시 추출해 동일 Wiki의 해당 파일만 메모리상 대체한 색인으로 검사했다.
관련 없는 업로드 문서나 발표 자료는 변경하지 않았다.

### 재현된 원인

1. PDF 기본 추출에서 표·본문의 줄 경계가 사라졌다. 시상 표의 대상명과 수치가
   긴 문자열로 이어져 검색어와 매칭되지 않았고, 실제 시상 페이지 대신 파일명만
   담긴 가져오기 메타데이터가 1위였다.
2. 수치 검증은 답변의 출처 괄호까지 읽어 `PDF 2페이지`의 `2페이지`를
   본문 수치로 검사했다. 정작 띄어 쓴 `500만 원`, `20팀` 등은 놓쳤다.
3. `시간`이라는 단어가 포함되면 행사 일정도 모델 처리시간 표 검증으로 보냈다.
4. 수치가 같은 페이지 어디엔가 존재하는지만으로는 대상별 연결을 증명하지 못한다.
5. 실제 1.7B 생성에서 관련 페이지가 검색돼도 표지나 다른 페이지를 출처로 선택하거나
   시작일을 마감일처럼 답하는 문제가 추가로 관찰됐다. 작은 문맥에서의 경쟁 근거가
   원인 후보지만, 입력 토큰 잘림을 직접 계측해 확정한 것은 아니다.

이전 커밋의 검증 코드를 별도로 불러 동일한 재현 답변을 대조했다.
페이지 출처를 포함한 정상 답변은 `False → True`, 근거 없는 금액·팀 수는
`None → False`, 정상 행사 날짜 답변은 `False → True`였다.
원래 차단된 모델 본문은 서버가 보존하지 않으므로 해당 본문까지 재현했다고
주장하지 않는다. 이 대조는 명시적으로 구성한 재현 문자열의 검사 결과다.

## 구현

- PDF 추출에 pypdf `layout` 모드를 사용해 물리적 행과 열 간격을 보존한다.
  OCR·표 구조의 완전한 복원을 추가한 것은 아니다.
- 자동 업로드 형식의 파일명·가져온 시각·형식 메타데이터만 색인에서 제외한다.
  파일과 페이지 출처는 유지하며 일반 Markdown의 인용문을 제거하지 않는다.
- PDF 프롬프트는 물리적 줄을 보존하고 여백만 줄인다. 동일 업로드 PDF의
  페이지들만 검색됐으면 상위 페이지 중심으로 생성한다. 다른 문서가 섞였거나
  모델·연도 조건 때문에 첫 페이지로 축약할 수 없으면 기존 경로를 유지한다.
  문맥 정책과 원래 검색/전달 개수·한계는 응답 `context`에 기록한다.
  직접 `grounded_response`를 호출하는 고정 문맥 실험은 바꾸지 않는다.
- 출처 괄호는 수치 주장 추출에서 제외하되, 출처 번호·파일/제목 검사는 유지한다.
- 띄어 쓴 금액, 팀·명·인·세·점·회·부 수량, 점/슬래시/하이픈 날짜,
  연도 생략 한국어 날짜를 인식한다. 일정 범위의 끝 연도는 같은 줄의 명시적
  범위에 한해서만 상속한다. 문서 제목의 연도로 추측하지 않는다.
- 숫자 일부의 부분문자열 일치를 없앤다. `120만원`으로 `20만원`을 승인하지 않는다.
  원문에서 같은 행의 수량·금액이 명시된 지원 형식이면 대상별 연결도 검사한다.
- 행사 날짜·마감·시각과 처리 소요시간을 구분하며, 실패한 수치 검사의 표시를
  ‘검증 통과’로 내보내지 않는다.
- PDF의 명시적 수량·금액 행, 지급 문단, 장소·시간 미공개 문단과 관련 일정은
  제한적으로 직접 복사한다. 값·행사명·문서명·정답은 운영 코드에 넣지 않았다.
  원문의 `점`을 `팀`으로 환산하지 않으며 전체 의미·단위 환산은 미확인으로 남긴다.
  미공개 문단에 붙은 무관한 OT 설명은 함께 복사하지 않는다.
- 요청한 한도 수치를 생성했으나 근거 검증에 실패하면, 숫자를 숨기고 요청한 한도
  값을 검색된 근거로 확인하지 못했다고 설명한다. 전체 문서에 정보가 없음을
  증명한 것으로 표현하지 않는다.

## 실제 실행과 남은 한계

실제 USB 1.7B 호출은 두 단계에서 각 5문항, 총 10회로 끝냈다. 모델을 바꾸거나
다운로드하지 않았고, 서버를 종료·재시작하지 않았다. 성능 벤치마크가 아니다.

- 수치·추출 수정 후 첫 5회: 잘못된 수치 4개 응답은 차단됐지만 2번은 표지의
  날짜를 마감처럼 답했다. 이 결과를 성공으로 보고하지 않는다.
- 페이지 중심 전달 후 5회: 1번은 자격·인원, 2번은 접수 기간·18시·PDF 분량을
  표시했다. 2번은 데이터 활용 명세를 생략했으므로 완전한 답변이라고 하지 않는다.
  3번은 잘못된 팀 수로 차단, 4번은 날짜·서울을 표시했으나 미공개 세부 시간 누락과
  잘못된 과거 시제 표현이 남았고, 5번은 근거 없는 호출 한도를 생성해 차단됐다.
- 이후 3·4번은 모델 추가 생성 없이 원문 복사 경로로 보완했다. 실제 재추출된
  PDF에서 수량/금액/지급 문구, 본선 일정과 미공개 장소·시간 안내를 분리하는
  부분 답변을 확인했다. 문서의 수량 단위를 그대로 유지한다.
- 연도 생략 날짜 검증과 한도 차단 안내도 마지막 회귀에서 보완했다.
  마지막 코드 전체로 실제 모델 5회를 다시 돌리지는 않았다. 따라서 이번 작업을
  ‘최종 실제 5문항 전부 통과’라고 보고하지 않는다.

pytest 전체 535개 통과(추가 36개). 별도 행사명·수치의 통제 예시로 수치 인식,
잘못된 행 연결, 출처 페이지, 날짜 범위, 메타데이터 배제, PDF 페이지 정책과
고정 문맥 보존을 확인했다. FastAPI/Flask 테스트 클라이언트에서도 원문 복사
2유형의 스트리밍 응답·출처·부분 검증·완료 이벤트를 검사했다.

이 검증은 일반 자연어 의미, 날짜의 역할, 답변 완전성, 문서 최신성을 보장하지 않는다.
지원하지 않는 표/문장/복합 질문에서는 보수적 보류나 추가 오류가 남을 수 있다.
특히 PDF 전반을 종합해야 하는 질문에 상위 한 페이지가 충분하다고 보장하지 않는다.
기존 Wiki 사례만으로 정확도가 높아졌다고 평가하지 않는다.

## 사용자 재확인

### 최종 화면 확인 결과

사용자의 첫 재업로드에서는 수정 전 동작이 계속 보였다. 저장 파일의 가져오기
시각만 갱신되고 추출 내용은 이전의 한 줄 형식인 것을 확인했다. 오래된 서버가
계속 실행 중인 것으로 추정했으며, 정확한 경로에서 재시작·재업로드하도록 안내했다.
그 뒤 사용자가 공유한 화면에서 새 원문 복사 경로가 적용됐음을 확인했다.
실행 프로세스의 PID·경로는 권한 제한으로 직접 확정하지 않았다.

| 문항 | 사용자 최종 화면에서 확인한 동작 | 남은 한계 |
|---|---|---|
| 1 참가 자격 | 나이·국적·거주·기업 제외·2~4인 제한 표시 | 원문 전체의 의미·조건 완전성을 자동 검증한 것은 아님 |
| 2 마감·제출 | 접수 기간과 마감 18시, PDF·약 10페이지 표시 | 데이터 활용 명세 제출 누락. 완전한 답변으로 판정하지 않음 |
| 3 시상 | 대상·최우수상·우수상의 원문 행과 지급 방식 표시 | `점`을 `팀`으로 환산하지 않은 부분 답변 |
| 4 본선 | 본선 발표·시상 일정과 서울·추후 공개 안내 분리 | 정확한 장소·시작 시간은 미확인 유지 |
| 5 호출 한도 | 검색 근거로 한도 값을 확인하지 못했다고 안내 | 임의 숫자는 미표시, 전체 문서의 정보 부재를 증명한 것은 아님 |

기존 5문항의 최종 코드 화면 확인은 완료했다. **5문항 전부 완전 정답**으로
보고하지 않으며, 주요 오류 수정 확인과 2번의 제출 항목 누락을 함께 기록한다.
사용자의 재업로드는 기존 파생 Markdown을 새 추출 형식으로 갱신하므로 위의
당시 업로드 해시와 현재 파일 해시가 달라질 수 있다. 원본 PDF는 바꾸지 않는다.

### 재실행 절차

1. 실행 중인 웹 서버 창에서 Ctrl+C 후 기존 명령으로 한 번 재시작한다.
2. 같은 PDF를 다시 업로드한다. 동일 바이트·파일명이면 기존 해시 경로의 파생
   Markdown이 새 추출 방식으로 갱신된다. 원본 PDF는 변경되지 않는다.
3. 1.7B·Wiki 근거 사용 상태에서 기존 질문 5개를 한 번씩 다시 확인한다.
   3번은 원문 단위 보존, 4번은 날짜와 미공개 항목 분리,
   5번은 임의 호출 한도 미표시를 우선 본다.

재색인만으로는 오래된 추출 텍스트가 새 형식으로 바뀌지 않는다.
