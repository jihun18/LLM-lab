# 확인된 역할을 보존하는 부분 답변 개선 — 2026-10-16

## 문제와 변경 범위

[최초 품질 평가](FRESH-QUALITY-20261016.md)의 q03/q04/q09/q10은 역할 근거가 있어도 추가 요구 하나가 부족하면 확인된 역할까지 답하지 않았다. 원문 부분 추출 경로의 제한 문법이 ‘정리해줘’, ‘역할에 더해’, ‘같은 목록으로’, ‘최소 RSS 실측값도 덧붙여줘’, ‘그리고 함께 사용하는 설계 이유’를 지원하지 않아 전체 보류로 넘어간 것이 원인이다.

`core/requirement_retrieval.py`의 제한 문법에 표현을 추가했다. ‘실측값’은 메모리 요구가 있을 때, ‘설계/사용하는’은 이유 요구가 있을 때만 허용한다. 임의의 추가 요구를 무시하거나 일반 자연어 추론 범위를 넓히는 방식은 쓰지 않았다. 기존 원문 항목별 추출·출처 연결·미확인 항목 안내를 그대로 사용한다. 추출을 끈 고정 문맥 호출은 기존 메모리 보호 경로를 유지한다.

## 개발 회귀 결과

이 문항은 개선에 사용했으므로 **더 이상 독립 최초 평가가 아니라 개발 회귀**다. 기존 문항 파일·기대 항목·최초 보고서는 수정하지 않았다.

| ID | 변경 전 | 변경 후 |
|---|---|---|
| q03 | 최소 RSS 부족 안내만 하고 전체 차단 | Flask/Streamlit 역할과 실제 출처 제시, 각 최소 RSS는 부족 항목으로 유지 |
| q04 | Elysia 역할 부족만 안내, 확인된 역할 누락 | FastAPI/Streamlit 역할과 출처 제시, Elysia만 부족 항목으로 유지 |
| q09 | 평균 메모리 부족 안내만 하고 전체 차단 | 가상 두 도구의 역할과 출처 제시, 평균 메모리 부족 유지 |

## 검증과 한계

새 테스트 17개를 추가해 전체 **435개 통과**다. 위 4문항의 JSON 공통 응답 및 스트리밍 경로, 금지 수치 부재, 부족 항목·미완료 상태·실제 인용 일치를 확인했다. 추가 CPU·포트·API 문서·설계도 요구가 부분 추출에서 누락되지 않도록 미지원 상태를 유지하고, 원문 역할 충돌·2042년 조건·추출 비활성·보충 검색 횟수/모드 보호도 검증했다.

웹 서버를 시작하거나 브라우저로 새 화면을 확인하지는 않았다. 일반 의역 전체 지원이나 질문 전체 의미 보장은 아니다. q01/q07의 의역·기능 단정 문제는 이번 수정에 포함하지 않았다. 후속 독립 품질 평가는 다른 질문으로 해야 한다. Wiki·메모리 수집기·모델 옵션·평가 기준은 변경하지 않았다.
