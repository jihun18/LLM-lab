## 다음 개선 우선순위

1. 역할·메모리 질문의 `RSS`, `RAM`, `및`, `맡는 일` 표현을 공통 요구 분석과 부분 원문 추출에 연결한다. 메모리 근거가 없다고 이미 확인 가능한 역할까지 버리지 않아야 한다.
2. 역순 역할 목록 충돌은 위 공통 차단과 분리된 사례로 평가한다. 자유 서술의 의미를 자동으로 같거나 다르다고 단정하지 않는다.
3. 쉼표 숫자 형식 지원 여부는 별도 결정한다. 현재 안전한 보류를 완전한 추출 성공으로 집계하지 않는다.

이번 평가에서는 결과에 맞춰 운영 코드나 기준을 수정하지 않았다. 기존 테스트는 `213 passed`이며 새 경계 평가의 실패와 구분한다. 평가 도구에는 다른 기준 파일을 지정하는 옵션만 추가했다. 발표자료는 변경하지 않았다.

## 이후 개선과 회귀 확인

최초 평가를 마친 뒤 사용자 요청에 따라 아래를 구현했다. 위 최초 결과와 문항 기준은 바꾸지 않았다.

- 제한 문법에 RSS·RAM(대소문자 무관), ‘및’, 주격 ‘이’, ‘원문 근거로’, ‘확인해줘’를 연결했다. 기존 ‘맡는 일’ 인식도 이 문법으로 끝까지 통과한다.
- 역할+메모리 요구는 최초 검색에 역할 근거가 없어도 **추가 검색 시작 단계만** 허용한다. 원문 추출 자체는 여전히 실제 역할 근거가 있어야 한다. 숫자 메모를 역할로 인정하지 않는다.
- 보충 검색의 최대 4회·각 3개 결과·새 근거 최대 6개 제한과 사용자 검색 모드는 유지한다.
- `- 역할: **영문 대상명** — 설명`이라는 명시적 역순 목록만 후보에 포함한다. 일반 `- 설명: **대상명**`이나 자유 서술의 의미는 새로 추론하지 않는다. 충돌은 원문 값 미선택으로 안내한다.
- 미지원 추가 요구는 여전히 공통 안전 안내로 남기며 질문 전체 완료로 표시하지 않는다. 근거가 없을 때 모델이 메모리 수치를 생성하지 않는 보호도 유지한다.
