# 제출 안내 누락 후속 개선 — 2026-10-22

## 목적과 범위

이전 PDF 5문항 재확인에서 2번은 접수 기간·PDF 형식·분량을 답했지만
데이터 활용 명세 제출을 빠뜨렸다. 이 후속 작업은 제출 안내의 관련 목록을
보존하는 범위에 한정한다. 특정 대회의 서류명·정답·날짜는 운영 코드에 넣지 않는다.

## 변경

- 질문에 제출 서류·제출 자료·구비 서류·제출해야 할 서류가 명시된 경우,
  업로드 PDF의 검색된 제출 안내 구간을 원문 복사 경로로 처리한다.
- 신청/접수 방법, 제출 안내/서류/자료, 구비 서류 제목과 명시적 제출 라벨을
  지원한다. 다음 절 제목으로 경계를 제한해 심사·문의 절을 함께 가져오지 않는다.
- 1차·2차 등 요청 단계가 있으면 단계 이전의 공통 안내와 요청 단계의 목록을
  유지하고 다른 단계 전용 목록은 제외한다. 요청 단계를 찾지 못하면 미확인 표시한다.
- 문장이 여러 줄로 나뉘거나 목록 뒤에 추가 자료·동의 항목이 있어도
  해당 구간 전체를 보존한다. 짧은 생성 요약이나 세 문장 제한으로 서류를 생략하지 않는다.
- 일정도 요청한 경우에는 접수/신청/제출과 날짜가 함께 적힌 명시적 행을 같이
  복사한다. 시작일을 마감일로 바꾸어 부르거나 없는 날짜를 만들지 않는다.
- 현재는 검색된 동일 업로드 PDF 페이지들에 한정한다. 추가적인 문서 전수 탐색이나
  모델 재생성은 하지 않는다. 원본과 업로드 파일은 수정하지 않는다.

검색된 안내 밖의 추가 서류·최신성·요청 전체의 완전성은 미확인으로 남기므로
응답은 부분 답변이다. 지원하지 않는 절/단계/일정 형식과 여러 페이지에 걸쳐
나뉜 목록에는 추가 누락 가능성이 있다. 검색된 구간을 보존했다는 사실을
문서 전체의 완전성 검증으로 해석하지 않는다.

## 검증

- 전체 pytest **549개 통과**. 추가 14개는 별도의 연구 공모 예시를 사용한다.
- 여러 줄로 나뉜 재료 사용 명세·안전 확인서·동의 항목 보존,
  공통/1차/2차 분리, 단계 미지정·없는 단계, Markdown 하위 단계 제목,
  제목 없는 제출 라벨, 무관한 날짜 미사용을 검사했다.
- 일반 응답과 스트리밍에서 모델을 호출하지 않고 원문·출처·부분 답변 상태를
  확인했다. FastAPI·Flask 테스트 클라이언트의 실제 앱 경로도 검사했다.
- 현재 업로드된 요강에 기존 2번 질문을 적용한 서비스 호출에서도
  기획안/PDF/분량, 동의·제안서·데이터 활용 명세, 접수 일정이 원문 그대로
  포함되는 것을 확인했다. `eval_count=0`, `answer_status=partial`였다.
- 사용자가 서버 재시작 후 공유한 2번 질문의 상단·하단 화면에서 기획안/PDF/분량,
  필수 동의 항목, 데이터 활용 명세 및 접수 일정이 포함되는 것을 재확인했다.
  문서 전체 완전성 미확인 안내도 유지됐다. 화면 확인까지 완료했으며,
  독립적인 새 평가나 일반 의미 정확도 검증으로 해석하지 않는다.
- 에이전트가 실행 중인 서버를 종료하거나 재시작하지 않았다. 추가 Ollama 생성 실험은 없다.

## 재확인

서버를 재시작하고 기존 **2번 질문만** 다시 입력한다.
이번에는 추출 방식이나 업로드 파일을 바꾸지 않았으므로, 이미 layout 방식으로
재업로드한 동일 문서를 다시 올릴 필요는 없다.

형식·분량뿐 아니라 동의 및 추가 제출 자료가 포함되는지, 관련 없는 다음 절이나
다른 단계의 서류를 섞지 않는지 확인한다. 이 재확인은 이미 개발에 사용한 문항이며
새 독립 평가 점수로 보고하지 않는다.
