# 명시적 근거 번호 선택으로 출처 오기 감소

작업일: 2026-10-06

## 발견한 문제

사용자의 웹 테스트에서 `FastAPI와 Flask의 역할과 차이를 설명해줘.`에 대해 모델이
`11-v0.1.0-Milestone.md`를 `11-v0.0.0-milestone.md`로 잘못 인용해 차단됐다.
모델에게 파일명·절 제목 전체를 재생성시키는 방식은 숫자와 긴 제목 오기에 취약했다.

## 구현

1. 근거 번호는 실제 전달한 검색 결과 순서에서 부여한다.
2. 로컬 Ollama에 JSON schema 형식으로 `answer`와 `source_id` 출력을 요청한다.
3. 서버는 필드·타입·빈 답변·범위·답변 본문의 별도 출처 괄호를 검사한다.
4. 유효한 번호만 해당 문서명·절 제목으로 변환한다. 화면의 사용 근거도 선택한 절만 표시한다.
5. 번호 0은 정확한 근거 없음 응답에만 허용한다. 누락·형식 오류·잘못된 번호는 차단한다.

파일명 오기를 유사도나 버전 번호 추측으로 다른 문서에 붙이지 않는다. 생성 서비스에서는
출처 누락 자동 부착과 같은 파일의 임의 절 제목 교정도 하지 않는다. 일부 과거 직접 검증
호출의 호환 동작은 유지하지만 서비스는 `require_explicit=True`로 엄격하게 호출한다.
단순 원문 추출·표 수치 직접 추출 경로는 기존처럼 모델 호출 없이 정확한 출처를 만든다.

근거 선택은 **출처 식별**이지 문장 의미 검증이 아니다. 선택 절에 대한 수치 검사와
실제 전달 근거의 명시적 역할 모순 검사를 계속 수행한다. 남는 서술문은 사람 의미 검토 상태다.

## 실제 실험과 남은 문제

- 안내 문구와 짧은 인용 번호만 쓰게 한 첫 시도는 두 질문 모두 출처를 누락했다.
- 구조화된 출력으로 보강한 뒤 두 복합 질문에서 유효한 번호와 정확한 출처가 표시됐다.
- 첫 질문에서는 Flask에 Streamlit의 역할을 붙이는 내용 오류가 남았다. 두 번째는 함께 사용하는
  이유를 충분히 설명하지 않고 속도 설명을 덧붙였다. 출처 성공을 답변 정확도 성공으로 기록하지 않는다.
- 브라우저에서 첫 질문을 실제 실행해 문서명·절 제목 표시와 콘솔 오류 없음, HTTP 200을 확인했다.
  그 답변에도 `Flask는 간단한 기능만 구현할 수 있다` 같은 원문에 없는 주장이 있었다.

첫 시도: 로컬 `citation-selection-20261006-153256.json`.
구조화 출력: 로컬 `citation-selection-20261006-153535.json`.
각각 개발 질문 두 개이며 독립 정확도·속도 비교 실험이 아니다. 원문 모델 출력과 화면 답변을 분리해 저장한다.

전체 자동 테스트 **120개 통과**. 잘못된 번호·누락·혼합 출처·잘못된 절·형식 오류·bool
번호·실제 요청 schema·올바른 출처지만 틀린 역할 등을 확인했다.

## 주의

기존 평가와 출력 형식이 달라져 기존 점수와 직접 비교하면 안 된다. 비교 도구는
`citation_format=structured_json`을 기록한다. `context.prompt_characters`는 기본 근거
프롬프트 길이이며 클라이언트가 덧붙인 JSON schema 지시 길이는 포함하지 않는다.
실제 입력 토큰은 Ollama의 `prompt_eval_count`로 확인한다.

최신 서버를 실행했으며 코드 변경은 아직 커밋하지 않았다. 다음 개선 대상은 복합 질문의
원문 밖 주장과 답변 완전성이다. 구조화 출력만으로 이 문제까지 해결되었다고 볼 수 없다.

기술 근거: [Ollama 구조화 출력 공식 문서](https://docs.ollama.com/capabilities/structured-outputs).
