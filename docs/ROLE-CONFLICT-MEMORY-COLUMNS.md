# 역할 표·목록 충돌 및 메모리 표 형식 개선

작업일: 2026-10-07. 직전 커밋: `5b532f3`.

## 구현 범위

- 역할 비교표와 `- 영문대상명: 역할` 형태의 목록에서 같은 대상의 값을 함께 대조한다.
  표 우선으로 다르게 적힌 역할을 임의 선택하지 않는다.
- 일부 역할만 다르면 다른 확인 항목은 원문으로 제시하고 충돌 항목은 부분 답변으로 표시한다.
  모든 역할이 충돌하거나 제한 문법 밖이면 생성 없이 역할 충돌 안내로 차단한다.
- 단순 비교·텍스트 추출·고정 근거 호출로 충돌 보호를 우회하지 못하도록 서비스 앞단과
  직접 비교표 추출기에 공통 검사를 적용한다.
- 메모리 표의 도구명 열을 헤더로 찾는다. 지원 헤더는 도구·프레임워크·대상·대상명·도구명·tool·framework다.
  도구명 열이 정확히 하나인 경우에만 처리하며, 열 위치를 바꿔도 모델 등 다른 조건을 보존한다.
- KiB를 추가 지원한다. 원문 단위를 그대로 복사하며 MB/KB 등으로 환산하지 않는다.
  %·PC RAM·모델 크기·유사한 다른 도구 이름을 대상별 측정 값으로 사용하지 않는다.

## 표현 차이와 실제 의미 충돌의 구분

공백·Markdown 강조·영문 대소문자를 정규화하고, 현재 Wiki의 두 표현 쌍만
명시적으로 같은 키로 취급한다: `최소 비교군`/`최소 구현 비교`,
`빠른 데모 UI`/`빠른 AI UI`. 이 경우에도 표시하는 값은 실제 원문 그대로다.

그 외 다르게 적힌 값을 `원문 값 충돌`로 표시한다. 두 표현이 실제로 동의어인지,
서로 양립하는지 자동으로 판단하지 않는다. 그러므로 이 표시는 의미 모순의 확정이 아니다.
`역할: **대상**` 역방향 목록과 자유 서술 전체의 교차 의미 모순 검사는 이번 범위에 포함하지 않는다.
명시적 의미 대조가 필요한 새 표현은 추가 검토해야 한다.

## 검증과 실행

- 추가 회귀 검사 14개, 전체 테스트 213개 통과
- 기존 최초 평가 실패 n07(도구명 두 번째 열), n08(KiB), n10(표·목록 충돌)을 회귀로 전환해 모두 항목 검사 통과
- 결과: `benchmark-results/edge-holdout-20261007-162737.json`
- 최초 질문·기대 문자열과 원래 평가 보고서는 수정하지 않았다. 이번 통과는 독립 평가가 아니다.
- 통제 측정 값은 테스트 메모리 안에만 있으며 실제 Wiki에 가상 측정 문서를 넣지 않았다.
- 최신 FastAPI 서버를 127.0.0.1:8000으로 실행했다. 기존 역할 비교와 새 ‘맡는 작업+메모리’ 질문을
  브라우저에서 전송해 출처·원문 추출/부분 답변 표시를 확인했다. 두 스트리밍 POST는 HTTP 200,
  브라우저 콘솔 오류는 없었다.
- UI 화면은 실제 Wiki의 역할과 메모리 부족 안내다. 표 열·KiB·충돌 사례는 통제 근거 테스트로 검증했다.

실제 동일 조건의 메모리·전체 응답시간 측정 근거는 여전히 부족하며, 이번 수정이 측정 데이터를 추가한 것은 아니다.
