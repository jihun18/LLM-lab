# 질문의 대상 문서 선택 — 2026-10-22

## 배경

문서명을 생략한 표현 변경 3문항에서 앱 업로드 설명을 답한 검색 이탈,
모순된 답변, 마감 시각 누락이 관찰됐다. 직전 질문이나 마지막 업로드 문서를
자동으로 대화 문맥에 반영한다고 가정하지 않고 사용자가 범위를 선택하게 했다.
이 작업은 검색 범위의 혼선을 먼저 해결하며 자연어 의역 정확도·모순·누락까지
전부 해결했다고 주장하지 않는다.

## 화면 및 API

- FastAPI·Flask 공통 화면에 ‘대상 문서’ 선택기를 추가했다.
- 기본값은 ‘전체 Wiki·업로드 문서’로 기존 검색을 유지한다. 선택 가능한 문서는
  기존 `/documents`의 업로드 목록이다. 업로드가 성공하면 해당 문서를 자동 선택한다.
- 문서를 선택하면 RAG 요청에 선택 문서의 정확한 `source` 식별자를 보낸다.
  이름은 데이터이며 경로를 열거나 명령으로 실행하지 않는다.
- 일반 채팅에서는 선택기를 비활성화하고 `source`를 보내지 않는다.
- 답변 카드마다 요청 당시의 검색 범위를 표시한다. 생성 중에 선택기를 바꾸어도
  이미 진행 중인 요청의 범위가 바뀌지 않는다.
- 스트리밍 응답이 선택한 범위를 확인해주지 않거나 다른 문서의 출처를 돌려주면
  해당 답변을 표시하지 않고 오류 처리한다. 구형 서버가 새 선택 필드를 무시하는
  경우도 포함한다. 범위 확인 전에는 선택 문서 응답 본문을 임시로 노출하지 않는다.
- 문서 목록 요청이 실패하거나 선택 문서가 목록에서 사라져도, 선택을 몰래 전체
  검색으로 바꾸지 않는다. 새로고침 시의 초기값은 전체 범위이며 다시 선택해야 한다.

## 서버의 범위 보장

`RagRequest.source`는 선택적 필드다. 생략하거나 null이면 기존 전체 검색이며,
선택할 때는 색인에 있는 업로드 Markdown의 정확한 상대 식별자를 사용한다.
없는 문서·잘못된 경로·빈 문자열은 오류로 처리하며 다른 문서로 대체하지 않는다.

요청마다 색인의 얕은 복사본에서 선택 문서의 조각만 남기고 문서 빈도·평균 길이·
최신 날짜 등 순위 통계를 다시 계산한다. top-k 검색 후 필터링하는 방식이 아니다.
BM25·의미·하이브리드 검색 모두 제한된 조각에서 시작하며 보충 검색도 같은
범위를 사용한다. 의미 검색은 선택 조각만 임베딩·순위 계산하고 기존 캐시와
재진입 잠금은 공유한다. 원래 색인을 직접 축소하거나 전체 파일을 다시 읽지 않는다.

일반 응답과 스트리밍에 `document_scope`를 반환한다. 선택 문서 안에서 근거가
없으면 근거 없음으로 종료한다. 이는 색인 스냅샷 기준이며, 문서를 디스크에서
삭제만 하고 재색인하지 않았다면 오래된 색인이 남을 수 있다.

이 기능은 접근 권한·암호화 장치가 아니라 현재 로컬 앱의 검색 범위 선택 기능이다.
파일 원문·모델·지식 문서를 변경하지 않았다. Streamlit의 별도 화면에는 선택기를
추가하지 않았으며 이번 화면 대상은 FastAPI/Flask 공통 HTML이다.

## 검증

- 전체 pytest **571개 통과**, 추가 22개. 순위 계산 전 제한, 근거 없음, 잘못된
  경로/없는 문서, 요청별 색인 독립성, 보충 검색 누출 방지, 3개 검색 모드,
  동시 문서 선택을 검사했다.
- FastAPI·Flask 실제 앱의 테스트 클라이언트에서 일반/스트리밍 요청의 범위·
  출처·오류 응답을 확인했다. 생성 모델은 금지한 상태에서 검사했다.
- 격리 Chrome에서 선택 값 전송·응답 범위 표시·구형 서버 및 출처 불일치 차단·
  일반 채팅 미적용·업로드 후 자동 선택·기존 부분 답변/중단/모바일을 확인했다.
  브라우저 응답은 모의 데이터이며 실제 Ollama 종단 검증은 아니다.
- 실제 실행 중인 서버를 종료·재시작하지 않았고 원본 PDF를 재업로드하지 않았다.
  표현 변경 3문항의 새 실제 답변과 사용자의 최종 화면 확인은 아직 남아 있다.

후속 사용자 화면에서 충분 여부 질문의 선택 문서·검색 범위·출처가 요강으로
일치하는 것은 확인했다. 그러나 답변의 모순과 추가 자료 누락은 남아 있었다.
검색 범위 적용 성공을 답변 의미 정확도 성공으로 바꾸어 기록하지 않는다.
이후 [제출 안내 표현 후속](SUBMISSION-COMPLETENESS-20261022.md)에서 해당 경로를
별도로 보완했다. 표현 변경 3문항 전체의 새로운 실제 답변 확인은 아직 남아 있다.

그 보완 후 사용자가 공유한 충분 여부 질문 화면에서는 선택 문서·출처·검색 범위와
추가 제출 자료·동의 항목이 함께 유지됐다. 이전 모순 답변이 원문 복사로 대체된
것을 해당 문항에서 확인했다. 나머지 표현 변경 2문항을 같은 최종 코드로
재확인한 것으로 확대하지 않는다.

## 사용자 재확인

1. 실행 중인 서버 창에서 Ctrl+C 후 기존 명령으로 다시 실행하고 페이지를 새로고침한다.
2. ‘대상 문서’에서 현재 업로드된 요강을 선택한다. 이번에는 재업로드할 필요가 없다.
3. 문서명을 생략했던 질문 3개를 다시 입력한다.
4. 카드의 검색 범위와 모든 출처가 선택 문서인지 확인한다.
5. 그 다음 내용의 완전성·모순·마감 시각을 별도로 평가한다. 범위 제한 성공과
   답변 의미 정확도를 같은 판정으로 합치지 않는다.

새로고침만 하고 서버가 예전 Python 코드를 유지하면 범위 확인 오류가 나타날 수 있다.
이 경우 기존 서버를 재시작해야 하며, 포트 충돌이 나면 새 서버를 중복 실행하지 않는다.
