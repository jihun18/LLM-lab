# 선택 문서의 빈 제출 검색 회복 — 2026-10-22

## 재현과 원인

사용자 화면에서 ‘처음 접수할 때 준비해야 하는 파일과 추가 자료를 빠짐없이
알려줘.’는 선택 문서를 유지했지만 근거 없음으로 끝났다. 다른 표현의 마감·서류
질문은 제출 안내와 18시를 표시했다. 두 결과를 동일하게 통과로 기록하지 않는다.

현재 색인에서 실패 질문을 재현하니 해당 문서 7개 페이지 모두 질문 토큰과의
교집합이 0이었다. `접수할`은 원문의 `접수`와, `파일·추가 자료`는 `기획안·데이터
활용 명세`와 일치하지 않았다. 초기 검색이 비어 원문 추출에 필요한 근거가
전달되지 않은 것이 원인이다. 모델이 답변을 생성하다 실패한 사례가 아니다.

## 변경

- 명시적으로 선택한 문서의 스냅샷에 선택 식별자를 보존한다.
- 지원하는 제출 의도로 인식됐고 최초 검색 결과가 빈 경우에만 제한된 절 제목
  보충 검색을 한다. 최대 2질의, 질의당 3개 결과, 중복 제외 최대 6조각이다.
- 질의는 일반적인 제출/구비 서류·신청 방법·제출 자료 표현을 사용한다.
  특정 문서명·날짜·정답이나 사용자 실패 문장 전체를 운영 코드에 넣지 않는다.
- 선택 문서의 같은 색인 스냅샷과 같은 검색 모드를 사용하고 다른 출처는 거른다.
  전체 파일을 다시 읽거나 다른 문서를 뒤져 채우지 않는다.
- BM25의 검색 필터나 의미·하이브리드의 하한을 낮추지 않는다. 의미 검색이
  실패했다고 BM25로 몰래 바꾸지 않는다. 검색 기준 문서/일반 토큰화도 변경하지 않는다.
- 원 질문의 모델·연도 조건을 보충 질의에 유지하고, 원 질문 조건의 기존 검사를
  검색 후에도 수행한다. 다른 연도·모델 근거로 대체할 수 없다.
- 선택 문서가 없는 전체 검색, 비대상 질문, 이미 결과가 있는 검색은 이 보충
  경로를 사용하지 않는다. 문서가 없거나 범위가 잘못된 경우의 오류도 유지한다.
- `retrieval_followups`에 보충 질의·추가 조각 수·사유를 기록한다.
  보충해도 근거가 없는 응답에도 추적 기록을 남긴다.

원문 답변은 기존 제출 안내 복사를 사용한다. 검색된 구간 밖의 추가 자료나 문서
전체 완전성은 여전히 미확인이다. 이 변경은 일반적인 의역 이해 또는 모든
검색 실패를 해결하는 기능이 아니며, 지원 절 형식 밖의 근거도 남을 수 있다.

## 검증

- 전체 pytest **599개 통과**. 추가 11개는 별도 연구 공모 예시를 사용한다.
- 초기 결과 0개에서 제출 안내 회복, 일반/스트리밍의 토큰 0개 부분 답변,
  다른 출처 배제, 모드·검색 한도·중복 제거, 비대상/전체 검색 미변경,
  근거 없는 문서의 보류, 연도 검사, 의미 검색의 빈 하한 유지 등을 확인했다.
- FastAPI·Flask 테스트 클라이언트에서도 선택 문서·추적 정보·명세 보존을 검사했다.
- 실제 현재 색인과 선택 요강에 실패 질문을 적용한 서비스 호출에서 첫 보충
  질의로 PDF 3페이지 1조각을 회복하고, 두 번째는 중복 외 새 조각이 없었다.
  제출 안내의 동의 항목·데이터 활용 명세가 보존됐고 생성 토큰은 0개였다.
- 원본·업로드 문서를 수정하거나 모델을 추가 호출하지 않았다. 에이전트가 서버를
  재시작하지 않았다. 이후 사용자가 공유한 상단·하단 화면에서 같은 실패 질문이
  제출 안내 원문으로 회복되고, 필수 동의·데이터 활용 명세·선택 문서 범위가
  유지됨을 확인했다. 화면은 0.016초와 token/s 미표시를 보였다.
- 이 개발 문항의 화면 확인은 완료했지만 모든 의역이나 다른 문서의 정확도를
  검증한 것으로 확대하지 않는다. 문서 전체 완전성 미확인 표시도 유지됐다.

## 사용자 확인

서버 재시작 → 페이지 새로고침 → 대상 요강 다시 선택 후, 실패했던 첫 질문만
다시 입력한다. PDF를 재업로드할 필요는 없다. 기존 실패 기록은 보존하며,
이 문항의 회복을 독립 평가 정확도 또는 모든 의역의 통과로 해석하지 않는다.
