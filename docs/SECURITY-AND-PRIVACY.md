# 보안과 개인정보 보호

## 기본 원칙

privAI의 핵심 목표는 문서와 질문을 외부 LLM API로 보내지 않는 것이다. 기본 구성에서 브라우저, FastAPI, Ollama와 Wiki는 같은 PC에서 실행된다.

## 로컬 데이터 흐름

```text
브라우저
→ 127.0.0.1:8000 FastAPI
→ 로컬 Wiki 검색
→ 127.0.0.1:11434 Ollama
→ 브라우저
```

코드에는 외부 LLM API 호출이 없다. 단, 운영체제, 브라우저, Ollama나 향후 추가 라이브러리의 별도 네트워크 동작까지 이 프로젝트가 보증하는 것은 아니다.

## 로컬 전용 바인딩

권장 실행 명령:

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

`0.0.0.0`으로 실행하면 같은 네트워크의 다른 기기에서 접근할 수 있으므로 인증 기능이 없는 v0.1.0에서는 사용하지 않는다.

## 업로드 보안

현재 방어:

- `.md`, `.txt`, `.pdf`만 허용
- 최대 5MB
- PDF 최대 100페이지
- 파일명 경로 구분자 차단
- 상위 폴더 이동 차단
- 안전한 파일명 변환
- 내용 SHA-256 기반 저장 이름
- 암호화 PDF 거부
- 텍스트 없는 PDF 안내
- 원본 PDF를 보존하지 않고 추출 Markdown만 저장

알려진 한계:

- PDF 파서 취약점 격리 없음
- 악성 문서 샌드박스 없음
- 업로드 파일 바이러스 검사 없음
- 스캔 PDF OCR 없음
- 다중 사용자별 저장소 격리 없음

신뢰할 수 없는 파일을 공개 서버에서 받는 용도로 사용하면 안 된다.

## Git 제외 정책

다음 데이터는 공개 저장소에 포함하지 않는다.

```gitignore
.venv/
.env
benchmark-results/*
wiki/Uploads/*
*.log
```

`wiki/Uploads/.gitkeep`만 폴더 구조 유지를 위해 포함한다. 공개 데모 문서는 `samples/`에 별도로 둔다.

## 모델 답변 신뢰 정책

모델이 출처를 인용해도 답변 전체를 자동으로 사실로 간주하지 않는다.

- 표 수치: 열 이름과 질문 단위를 구조적으로 대응
- 금액·날짜·단위: 근거 원문 문자열과 대조
- 일반 서술문: 사람 의미 검토 필요로 표시
- 근거 없음: 추측 대신 근거를 찾지 못했다고 응답

현재 검증은 문장 의미 전체, 부정 표현, 인과관계와 수치 환산을 완전히 이해하지 못한다.

## GitHub 공개 전 점검표

- [ ] `git status`에서 `wiki/Uploads` 문서가 제외됐는지 확인
- [ ] `.env`, API 키, 이메일과 사용자 경로 검색
- [ ] 스크린샷에서 계정명·개인 문서명 제거
- [ ] 벤치마크 답변에 개인정보가 없는지 확인
- [ ] `samples/`가 가상 데이터인지 확인
- [ ] Ollama 모델 파일이 포함되지 않았는지 확인
- [ ] 라이선스 결정
- [ ] 새 환경에서 설치 절차 재현
- [ ] 테스트 통과

PowerShell 점검 예시:

```powershell
git status --short
git ls-files
```

## 사고 대응

개인 문서가 실수로 커밋됐지만 아직 원격에 올리지 않았다면 해당 파일을 Git 인덱스에서 제외하고 `.gitignore`를 확인한다. 원격에 이미 올라갔다면 단순 삭제 커밋만으로 과거 기록이 사라지지 않는다. 이 경우 저장소 공개를 중단하고 Git 기록 정리와 노출된 비밀값 교체를 먼저 수행해야 한다.
